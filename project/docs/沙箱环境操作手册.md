# api-relay 沙箱环境操作手册

> 适用：在隔离/演示环境（沙箱、临时 ECS、评审机）里把 api-relay v2（含 Agent v2）跑起来、验一遍、收尾清理。
> 面向不熟悉本仓库的操作者：**照抄命令即可**。所有命令区分 Linux（服务器/沙箱）与 Windows PowerShell（本机）。

---

## 1. 环境要求

| 项 | 要求 | 检查命令 |
|---|---|---|
| Node.js | **≥ 22.5.0**（`node:sqlite` 必需） | `node -v` |
| npm | ≥ 10（随 Node 附带） | `npm -v` |
| 磁盘 | ≥ 500 MB（源码+构建+KB/度量库） | `df -h .` |
| 网络 | 出站 HTTPS（拉上游 API；Demo 模式无需） | `curl -sI https://example.com` |
| 运行时依赖 | **0 个**（仅构建期需要 typescript/@types/node/tsx） | — |

> Windows 沙箱注意：`node:sqlite` 在 Windows 可用（本项目演示即 Windows 11 + PowerShell 开发），但**生产建议 Linux**（信号处理与 WAL 行为差异，见 `docs/DEPLOYMENT.md` §1）。

## 2. 取得代码

三种方式按场景选一：

```bash
# A. 压缩包直传（沙箱无 git 时最简）
#    本机先打包（PowerShell，排除依赖与生成物）：
#      tar -czf relay-src.tar.gz --exclude=node_modules -C <project目录> .
#    上传后解压：
mkdir -p /root/api-relay && tar -xzf relay-src.tar.gz -C /root/api-relay

# B. git（沙箱可达 GitHub 时）
git clone https://github.com/lizehao521/api-relay.git && cd api-relay

# C. 华为云 ECS（已部署过的机器）
ssh -i <私钥> root@<EIP>   # 代码在 /root/api-relay
```

## 4. 启动

### 4.1 Demo 模式（推荐沙箱首跑：无需任何密钥/配置）

```bash
cd /root/api-relay
setsid nohup node --disable-warning=ExperimentalWarning dist/cli.js demo --host 0.0.0.0 \
  > /root/api-relay.log 2>&1 < /dev/null &
sleep 5
```

单进程内同时跑：mock 上游 + 网关 + 管理面板 + **内部 Agent v2**。自动执行 5 项自检并打印结果。

**预期日志尾部**（全 ✓ 才算健康）：

```
自检结果
  ✓ 健康检查                         HTTP 200
  ✓ 正常请求（Pro 层）                  HTTP 200
  ✓ P3 失败归因（注入 429）           归因卡片 + 可执行动作 ✓
  ✓ P2 预检拦截（畸形 tool_calls）     拦截于上游之前 ✓
  ✓ 免费层纯管道（无归因）             错误体零附加 ✓
正在运行，按 Ctrl+C 退出…
```

### 4.2 生产模式（要真实上游时）

```bash
cp config/relay.example.yaml relay.yaml
$EDITOR relay.yaml            # 填 providers（{ENV:...} 插值，禁明文）
export DEEPSEEK_API_KEY=sk-...
export RELAY_ADMIN_TOKEN=$(openssl rand -hex 24)
node dist/cli.js check        # 部署前必跑：列出配置错误与缺失 env
node dist/cli.js serve
```

**Agent v2 配置**（追加进 relay.yaml）：

```yaml
agent:
  enabled: true
  clientId: ops-agent        # 必须与 clients 里一条 key 的 id 一致（D6 校验会拦拼写错误）
  model: <模型名>             # 必填（check 会报 error）
  intervalMs: 1800000        # 30 分钟巡检；<60s 会 warn
  llmTimeoutMs: 60000
  autoWriteKb: false         # v2 默认 false：仅人工确认写 KB
  kbId: kb_demo
  dailyTokenLimit: 200000    # 日 token 护栏（强烈建议设置）
  dailyCostCnyLimit: 5.0     # 日金额护栏（元）

clients:
  - id: ops-agent            # Agent 专用 key（走完整计量闭环）
    key: "{ENV:RELAY_AGENT_KEY}"
    tier: pro
```

> `relay check` 对 agent 的校验（v2 新增）：clientId 缺失/不存在、model 缺失 → **error**；interval < 1min、无日配额 → warn。

## 5. 验证（沙箱验收清单）

### 5.1 基础链路（Demo key）

```bash
B=http://127.0.0.1:8787

curl -s -o /dev/null -w '%{http_code}\n' $B/healthz                                   # 200
curl -s $B/v1/chat/completions -H "Authorization: Bearer sk-demo-pro" \
  -H 'content-type: application/json' \
  -d '{"model":"mock-small","messages":[{"role":"user","content":"hi"}]}' | head -c 300  # chat.completion JSON
curl -s $B/v1/chat/completions -H "Authorization: Bearer sk-demo-pro" \
  -H 'content-type: application/json' \
  -d '{"model":"mock-429","messages":[{"role":"user","content":"hi"}]}' | head -c 400    # 含 relay_attribution
curl -s -o /dev/null -w '%{http_code}\n' $B/v1/models -H "Authorization: Bearer sk-demo-pro"  # 200
curl -s -o /dev/null -w '%{http_code}\n' $B/admin                                      # 200
```

**429 归因预期**：`relay_attribution.failure_reason=rate_limited`、`suggested_next.action=retry_with_backoff`、`retryAfterMs=1000`。

### 5.2 Agent v2（面板/接口）

```bash
# 状态（含 v2 字段：promptVersion/maxToolSteps/quota/openFindings）
curl -s $B/admin/api/agent | head -c 600

# 手动触发一轮（202；409=上一轮还在跑；503=未启用）
curl -s -X POST $B/admin/api/agent -H 'content-type: application/json' -d '{}'

# 结果（LLM 一轮 10-20 秒后再查）
curl -s $B/admin/api/agent/last | head -c 800
curl -s "$B/admin/api/agent/runs?limit=5" | head -c 800

# v2 新端点：自身指标（成功率/p95/token/失败分类/发现项）
curl -s $B/admin/api/agent/metrics

# v2 新端点：发现项（未闭环清单）
curl -s "$B/admin/api/agent/findings?open=1"

# 打标（人在环反馈）
curl -s -X POST $B/admin/api/agent/findings/<id>/mark -H 'content-type: application/json' \
  -d '{"status":"resolved"}'
```

**注意**：管理接口免令牌仅限本机直连（127.0.0.1）；若沙箱经反代/隧道访问，须设 `RELAY_ADMIN_TOKEN` 并带 `X-Admin-Token` 头，否则 401。

## 6. 常见问题（沙箱高频）

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `node:sqlite` 不存在 | Node < 22.5 | 升级 Node（nvm install 22） |
| 端口被占（EADDRINUSE） | 8787 未释放 | `ss -ltnp | grep 8787` 找 PID → kill；或 `RELAY_PORT=8788` |
| `/admin/api/agent` 503 | agent.enabled 未开 | 配置里加 `agent:` 段并重启 |
| 触发 Agent 返回 409 | 上一轮还在跑（LLM 10-20s） | 等 30 秒再点/再 POST |
| Agent 每轮失败 `llm_http_4xx` | clientId 的 key 无效/被禁 | `relay check` 会报 error；核对 clients 段 |
| Agent 第二轮起 `quota_blocked` | 日配额耗尽（护栏生效） | 次日自动恢复；或调大 dailyTokenLimit |
| 重启后 Agent 历史为空 | 内存环重启即丢（by design） | `/agent/last` 有事件回退重建；完整史走事件库 |
| 面板"写入 KB"报 404 | kbId 对应库不存在 | 先在知识库页建 `kb_demo` |
| 健康检查 000/超时 | 防火墙/安全组没放行 | 放行 8787/tcp（云安全组 + 本机 ufw） |

## 7. 服务化（长期跑）

nohup 裸进程重启即丢，沙箱超过一天建议 systemd：

```bash
cat > /etc/systemd/system/api-relay.service << 'EOF'
[Unit]
Description=api-relay (OpenAI-compatible LLM gateway)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/api-relay
# 注意：不要加 ExecStartPre=node dist/cli.js check——demo 模式无上游会 check 失败导致起不来
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning dist/cli.js demo --host 0.0.0.0
Restart=always
RestartSec=2
KillSignal=SIGTERM
TimeoutStopSec=15
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now api-relay
systemctl is-active api-relay        # active (running)
```

## 8. 收尾清理（评审结束/沙箱回收）

```bash
# 停服务
systemctl disable --now api-relay 2>/dev/null; pkill -f 'dist/cli.js' 2>/dev/null

# 数据（度量/KB 库——含调用记录，按合规要求清）

# 整体回收（云沙箱直接销毁实例更省事）

```

## 9. 安全提醒（沙箱也别裸奔）

- **公网暴露必须 TLS**：客户端 key 走 `Authorization` 头，明文 HTTP 等于公开 key——用隧道或反代加证书；
- **必须设 `RELAY_ADMIN_TOKEN`**：不设则管理面只认"本机来源"，经反代/隧道时这不可靠（v2 修复的 C-04：`behindProxy: true` + 空令牌会拒绝启动）；
- **别开 `publicQuotaRemote`**：`/v1/quota` `/v1/panel` 会暴露用量与轨迹；
- Demo key（`sk-demo-*`）仅限演示，生产一律面板生成、明文只显示一次。
