### 5.1 抽屉焦点管理（frontend/src/drawer.tsx）

**现状**：`openDrawer` 只设 signal；`DrawerHost` 渲染的 `aside` 无 tabIndex、无焦点陷阱；`closeDrawer` 不归还焦点。键盘用户打开抽屉后焦点仍在触发处，Tab 会跑到抽屉底下的页面里。

**整文件替换**（现 41 行 → 约 80 行）：

```tsx
import { signal } from "@preact/signals";
import type { ComponentChildren } from "preact";
import { useEffect, useRef } from "preact/hooks";

/* ---------------- 右侧抽屉（signal 驱动，替代旧版 #drawer DOM 直插） ---------------- */

export interface DrawerOpts {
  title: ComponentChildren;
  body: ComponentChildren;
  foot?: ComponentChildren;
}

const drawerState = signal<DrawerOpts | null>(null);

/* 焦点归还：打开前记住触发元素，关闭后还回去（键盘用户不丢位置） */
let lastActive: HTMLElement | null = null;

export const openDrawer = (o: DrawerOpts) => {
  lastActive = document.activeElement as HTMLElement | null;
  drawerState.value = o;
};

export const closeDrawer = () => {
  drawerState.value = null;
  if (lastActive && document.contains(lastActive)) {
    lastActive.focus();
    lastActive = null;
  }
};

/* 抽屉是否打开——全局 Esc 逃生门需要先关抽屉再关侧栏，两处状态分属不同模块，由此查询 */
export const drawerOpen = () => drawerState.value != null;

export function DrawerHost() {
  const o = drawerState.value;
  const ref = useRef<HTMLElement | null>(null);

  /* 挂载后焦点移进抽屉：容器 tabIndex=-1 可获焦，屏幕阅读器立即进入对话框上下文 */
  useEffect(() => {
    if (o) ref.current?.focus();
  }, [o]);

  /* focus-trap：Tab / Shift+Tab 在抽屉内首尾可聚焦元素间循环，出不去了才叫模态 */
  const trap = (e: KeyboardEvent) => {
    if (e.key !== "Tab" || !ref.current) return;
    const f = ref.current.querySelectorAll<HTMLElement>(
      'button,[href],input,select,textarea,[tabindex]:not([tabindex="-1"])',
    );
    if (!f.length) return;
    const first = f[0];
    const last = f[f.length - 1];
    if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus(); }
    else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus(); }
  };

  if (!o) return null;
  return (
    <>
      <div id="scrim" class="on" onClick={closeDrawer} />
      <aside id="drawer" class="on" ref={ref} tabIndex={-1} role="dialog" aria-modal="true"
        aria-label={typeof o.title === "string" ? o.title : "详情"}
        onKeyDown={trap}>
        <div class="dh">
          <b>{o.title}</b>
          <button class="bare" onClick={closeDrawer}>关闭</button>
        </div>
        <div class="db">{o.body}</div>
        {o.foot ? <div class="df">{o.foot}</div> : null}
      </aside>
    </>
  );
}
```

**styles.css 追加**（全局 `:focus-visible` 会给 aside 画 2px 外框，容器获焦只为播报，不画）：

```css
/* 抽屉容器程序化获焦不画焦点框（行内真实控件仍保留 :focus-visible） */
#drawer:focus, #drawer:focus-visible { outline: none; }
```

**要点**：
- Esc 已在 main.tsx 全局处理（先关抽屉再关侧栏），closeDrawer 里的焦点归还自然生效，无需改 main.tsx。
- `aria-label` 只在 title 为纯字符串时给值；title 是 JSX 时回退 "详情"（aria-label 不接受 ComponentChildren）。
- 抽屉内容多是异步加载（如 Ledger 详情先 api 再 openDrawer），焦点落在容器而非首个控件，避免数据未到时焦点落在"关闭"上造成误关。

### 5.3 对比度实测脚本（scripts/contrast-check.mjs）

**现状**：两主题 20+ 颜色 token 无任何对比度校验，WCAG 达标全凭感觉。

**新文件 `scripts/contrast-check.mjs`**（零依赖，node 直接跑）：

```js
#!/usr/bin/env node
/* 5.3 对比度实测：解析 legacy.css 两个 :root 块的 token，按真实 UI 用到的前景/背景组合
   计算 WCAG 2.1 对比度。正文 <4.5 FAIL；大字号/图表色 <3.0 FAIL。
   用法：node scripts/contrast-check.mjs [--csv] 导出 CSV（带 BOM，Excel 直开） */

import { readFileSync } from "node:fs";

const CSS = readFileSync(new URL("../frontend/src/legacy.css", import.meta.url), "utf8");

/* 解析 :root 块（暗色）与 :root[data-theme="light"]（亮色）的 --token: #hex */
function parseTokens(selector) {
  const m = CSS.match(new RegExp(selector.replace(/[.*+?^${}()|[\]\\]/g, "\\$&") + "\\s*\\{([^}]*)\\}"));
  const out = {};
  if (m) for (const [, k, v] of m[1].matchAll(/--([\w-]+)\s*:\s*(#[0-9a-fA-F]{3,8})/g)) out[k] = v;
  return out;
}
const THEMES = { dark: parseTokens(":root"), light: parseTokens(':root[data-theme="light"]') };

/* WCAG 2.1 相对亮度与对比度 */
const lum = (hex) => {
  const n = hex.replace("#", "");
  const [r, g, b] = (n.length === 3 ? n.split("").map((c) => c + c) : n.match(/../g)).map((c) => parseInt(c, 16) / 255);
  const f = (c) => (c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4);
  return 0.2126 * f(r) + 0.7152 * f(g) + 0.0722 * f(b);
};
const ratio = (a, b) => {
  const [l1, l2] = [lum(a), lum(b)].sort((x, y) => y - x);
  return (l1 + 0.05) / (l2 + 0.05);
};

/* 真实 UI 色对（前景/背景/最小比值/用途）。token 名与 legacy.css 对齐，改色后跑此脚本即可回归 */
const PAIRS = [
  ["fg", "bg", 4.5, "正文/页面底"],
  ["fg", "panel", 4.5, "正文/卡片"],
  ["fg", "panel2", 4.5, "正文/悬浮行"],
  ["dim", "bg", 4.5, "次要文字/页面底"],
  ["dim", "panel", 4.5, "次要文字/卡片（th、note、hint 都在这）"],
  ["accent", "bg", 4.5, "链接/页面底"],
  ["accent", "panel", 4.5, "链接/卡片"],
  ["ok", "panel", 3.0, "成功态（多为粗体/图标）"],
  ["warn", "panel", 3.0, "警告态"],
  ["err", "panel", 4.5, "错误文字（细体也常见，从严）"],
  ["pur", "panel", 3.0, "紫色标记"],
];

const rows = [];
let fail = 0;
for (const [theme, tokens] of Object.entries(THEMES)) {
  for (const [fg, bg, min, use] of PAIRS) {
    const f = tokens[fg], b = tokens[bg];
    if (!f || !b) { rows.push([theme, fg + "/" + bg, "-", "-", "-", "TOKEN 缺失"]); fail++; continue; }
    const r = ratio(f, b);
    const ok = r >= min;
    if (!ok) fail++;
    rows.push([theme, fg + "/" + bg, f, b, r.toFixed(2) + ":1", ok ? "PASS" : `FAIL(<${min})`, use]);
  }
}

if (process.argv.includes("--csv")) {
  const bom = String.fromCharCode(0xfeff);
  const csv = bom + ["主题,色对,前景,背景,对比度,判定,用途", ...rows.map((r) => r.join(","))].join("\r\n");
  process.stdout.write(csv + "\n");
} else {
  const W = [6, 14, 8, 8, 9, 10];
  console.log(rows.map((r) => r.map((c, i) => String(c).padEnd(W[i] || 2)).join(" ")).join("\n"));
}
console.error(fail ? `\n${fail} 项未达标` : "\n全部达标");
process.exit(fail ? 1 : 0);
```

**package.json scripts 追加**：

```json
"check:contrast": "node scripts/contrast-check.mjs"
```

**预期首跑结果**（供校验脚本写对了没有）：GitHub 暗色调色板（#8b949e dim on #161b22 panel ≈ 4.6:1）大概率过线；亮色 #59636e on #ffffff ≈ 5.0:1 也应过；若真有 FAIL 项，那正是本脚本的价值——按用途调 token，重跑至全绿。

### 5.4 交互逻辑回归（frontend/src/ui-logic.ts + scripts/ui-logic.test.ts）

**现状**：rowA11y 的 Enter/Space 判定、toggleTheme 的切换、Esc 的层级顺序都是内联闭包，node:test 够不着（e2e 是 HTTP 级，无浏览器）。

**思路**：把三处纯判定抽到零依赖模块 `frontend/src/ui-logic.ts`（无 import、无 DOM、无 JSX），生产代码引用它；测试用 node 22 原生 `--experimental-strip-types` 直跑 .ts，不加任何 devDependency（守住零依赖原则）。

**新文件 `frontend/src/ui-logic.ts`**：

```ts
/* 纯交互判定（零依赖，node --experimental-strip-types 可直测）。
   ui.tsx/state.ts/main.tsx 从这里取逻辑，行为变更先在这里锁死再改 UI。 */

export type Theme = "dark" | "light";
export const nextTheme = (cur: Theme): Theme => (cur === "dark" ? "light" : "dark");

/* 键盘激活：Enter 立即激活；Space 需拦截默认滚动（keydown 拦、keyup 激活，对齐原生 button）。
   返回值：activate=触发动作；block=只拦滚动不触发；null=无关键放行 */
export function keyActivation(key: string): "activate" | "block" | null {
  if (key === "Enter") return "activate";
  if (key === " ") return "block";
  return null;
}

/* Esc 层级：抽屉开着先关抽屉；否则侧栏开着关侧栏；都没开不动 */
export function escAction(state: { drawer: boolean; nav: boolean }): "close-drawer" | "close-nav" | null {
  if (state.drawer) return "close-drawer";
  if (state.nav) return "close-nav";
  return null;
}
```

**接线**：
- `state.ts`：`Theme` 类型与切换改用 `nextTheme`（L25–33 的 `toggleTheme` 内部调用它；`Theme` 改从 ui-logic re-export 或直接 import）。
- `ui.tsx` `rowA11y`（L216–231）：keydown/keyup 里改调 `keyActivation(e.key)`——`activate` → preventDefault + onActivate()；`block` → keydown 只 preventDefault、keyup preventDefault + onActivate()。
- `main.tsx` 全局 Esc handler：改调 `escAction({ drawer: drawerOpen(), nav: navOpen.value })` 后按返回值执行。

### 5.5 表格行改 stretched-button（建议先实测再上）

**现状**：`tr role="button"` 是 WAI-ARIA 允许的模式，键盘已可达；但屏幕阅读器里行内容不会被当作按钮文字播报，且 `aria-label` 之外无原生按钮语义。

**方案**：每行首列加真实 `<button class="row-act">` 撑满整行，rowA11y 退化为纯属性生成器（去掉 role/tabIndex/键盘处理）：

```tsx
/* ui.tsx：rowA11y 瘦身后只负责 title 与 hover 类 */
export function rowA11y(title?: string) {
  return { class: "click" as const, title: title as string | undefined };
}

/* 调用处（Ledger/Diag/Providers/Kb×2 共 5 处）：首列单元格第一个子元素加 */
<td class="fit">
  <button class="row-act" onClick={() => onRowActivate()} aria-label="查看详情">{首列原内容}</button>
  {首列原内容保持渲染位置不变的话则 button 用空文本 aria-label}
</td>
```

**CSS**：

```css
tbody tr { position: relative; }
tr > td:first-child .row-act {
  position: absolute; inset: 0; z-index: 0;
  background: none; border: none; padding: 0; text-align: left; width: 100%; height: 100%;
  cursor: pointer;
}
/* 行内真实按钮浮到撑满层之上（Kb 行的编辑/删除、Ledger 行内按钮都靠这条） */
td .bare, td button:not(.row-act) { position: relative; z-index: 1; }
```

**⚠️ 风险（为何放第三批并建议实测）**：
1. `tr { position: relative }` 在旧 Safari 有布局 bug（14+ 才稳定）。
2. `.block` 卡片若有 overflow 裁切，absolute 撑满层会被裁。
3. 行内按钮 z-index 提升后，hover 态、列内边距需逐表核对（5 张表结构不同）。
4. 增益主要是屏读播报质量，键盘可达性 5.1+rowA11y 已解决——**性价比最低的一项**。

**建议**：5.1–5.4、5.6 落地后，用 NVDA/VoiceOver 实测 `tr role="button"` 播报效果，确实不可接受再上此项；若上，先在 Ledger 单表试点再铺开。

strictPort 场景下 pickPort 试 1 次失败返回 0（系统随机分配）——这不符合"报错"语义，需让 pickPort 在 strict 时抛错。改法（L63–69）：

```ts
async function pickPort(start: number, host: string, tries = 20): Promise<number> {
  for (let i = 0; i < tries; i++) {
    const p = start + i;
    if (await isPortFree(p, host)) return p;
  }
  if (tries === 1) throw new Error(`端口 ${start} 已被占用（显式指定的端口不自动更换：换一个端口，或停掉占用进程后重试）`);
  return 0; // 交给系统随机分配
}
```
