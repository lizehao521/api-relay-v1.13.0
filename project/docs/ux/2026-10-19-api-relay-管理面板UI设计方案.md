# api-relay 管理面板 UI 设计方案 v1.0

> 项目类型：API 网关运维管理面板（Web，桌面优先 + 移动可用）
> 日期：2026-10-19 · 状态：已随代码落地（壳层 + 设计系统），本文档为系统化规范
> 配套：布局已实现于 `frontend/src/main.tsx` + `styles.css`；tokens 见 `legacy.css`
> 依据：`docs/ARCHITECTURE.md`（模块职责）、`DESIGN.md`（红线）、实测 WCAG 对比度

---

## 0. 设计定位与核心原则

**用户是谁**：部署者/值班人。任务不是"逛"，是**在 30 秒内回答"现在能不能用、坏了的话坏在哪、下一步点什么"**。

**四个不可妥协的原则**（全部源自产品红线）：

| 原则 | 含义 | UI 上的体现 |
|---|---|---|
| 数据可信 | 成功响应零改写、正文不落盘 | 数字一律等宽字体 + tabular-nums；摘要可复制原文；密钥只显示一次 |
| 状态可见 | 系统状态永远可感知 | 顶栏"数据新鲜度"超 60s 变红；错误率全站一个色标口径 |
| 处置闭环 | 错误对 Agent 可执行 | 每个错误展示"发生了什么 + 为什么 + 去哪修"，横幅直接给跳转链接 |
| 降级可用 | 看板挂了不挡转发 | 加载失败给重试入口而非白屏；空态区分"没数据"和"没连上" |

**设计立场**：这是一个**驾驶舱（Cockpit）**而非营销页——信息密度中等偏高、去装饰、层级靠间距和字重而非色彩堆叠。全站只允许一个品牌强调色（蓝），其余颜色全部是**语义色**（状态指示），绝不用于装饰。

## 1. 界面布局

### 1.1 壳层结构（已实现）

```
┌───────────────────── TopBar 52px ─────────────────────┐
│ ☰  ⚡ api-relay 管理面板   v0.1.0 时钟 数据12s前 ↻ 退出 │  ← L1 全局
├──────────┬────────────────────────────────────────────┤
│ SideNav  │                                            │
│ 232px    │   main（唯一滚动区，内容 max-1200px 居中）     │  ← L2/L3
│          │                                            │
│ 监控 ⌄   │                                            │
│ 配置 ⌄   │                                            │
│ 智能 ⌄   │                                            │
│ 系统 ⌄   │                                            │
│ ──────── │                                            │
│ 窗口 ▾   │  ← 全局数据口径控件沉底                       │
└──────────┴────────────────────────────────────────────┘
```

CSS Grid `grid-template-areas: "top top" / "nav main"`，壳层 100dvh 不滚动，**main 是唯一滚动容器**——切页签回来不丢滚动位置。

### 1.2 三层信息层级

| 层 | 载体 | 内容 | 排布依据 |
|---|---|---|---|
| **L1 全局** | 顶栏 | 品牌、版本、时钟、**数据新鲜度**、刷新、退出 | 任何页签都需要一眼确认"数据是否还活着"；只读状态与操作按钮左右分区 |
| **L2 导航** | 侧栏 | 10 页签按 **监控 → 配置 → 智能 → 系统** 四组 | 值班心智动线：先看状态（总览/指标/账本/排障）→ 再改配置（Key/上游）→ 再管自动化（KB/Agent）→ 底层系统（运维/信任）。分组 ≤ 7 项（米勒法则），当前页左侧 3px 高亮条 + 14% 蓝底 |
| **L3 任务** | main | 当前页签内容 | 页内层级：状态横幅（若有）→ 指标卡 → 图表 → 明细表，按"结论先行"排序 |

**设计依据**：原布局 10 页签 + 8 控件挤一条 header，窄屏溢出换行、导航与数据控件混杂。拆分后：导航纵向永不溢出；**窗口/自动刷新/间隔三个"改变所有页签数据口径"的全局控件沉到侧栏底部**，与导航物理分离防误触；主内容获得完整宽度。

### 1.3 页内信息排序公式（所有列表页统一）

```
① 页头动作区（主操作按钮右置）
② 过滤器（状态 chips / 搜索框，改变下方表格）
③ 数据表（行内状态用 chip，数字右对齐等宽）
④ 行点击 → 右侧抽屉看详情（绝不跳页打断列表上下文）
```

### 1.4 响应式

| 断点 | 行为 |
|---|---|
| > 960px | 完整三区布局 |
| ≤ 960px | 侧栏收为抽屉（左滑出 + scrim 遮罩，切页签自动收起）；顶栏出 ☰；**收起版本号与时钟（手机状态栏已有），保留"数据新鲜度"**——它是值班最关键信号，加省略号截断 |
| 卡片网格 | `.cards` 4 列 → 1020px 起 2 列；`.two` 1.3fr/1fr → 单列 |
| 触控目标 | 按钮/复选框/行点击 ≥ 30px 命中区，checkbox 15×15 + label 扩大命中 |

## 2. 配色方案

**策略：暗色为默认主题**（运维工具长时间盯屏、监控语义色在暗底上更醒目），亮色主题同 token 结构一键切换（`data-theme="light"`）。

### 2.1 暗色主题（默认）

| 角色 | HEX | 对比度(实测) | 使用场景 |
|---|---|---|---|
| 背景 `--bg` | `#0d1117` | — | 页面最底层，纯衬托 |
| 面板 `--panel` | `#161b22` | — | 卡片/表格/抽屉/侧栏底色 |
| 面板2 `--panel2` | `#1b212a` | — | 行 hover、导航 hover、骨架屏底 |
| 边框 `--border` | `#30363d` | — | 卡片边框、表头下边线、分隔线 |
| 边框2 `--border2` | `#222831` | — | 表格行间细线（比 border 更弱，避免斑马纹感） |
| **正文 `--fg`** | `#e6edf3` | **16.02:1** | 标题、数值、表体 |
| **次要 `--dim`** | `#8b949e` | **6.15:1** | 标签、说明文字、时间戳、表头 |
| **品牌/强调 `--accent`** | `#58a6ff` | **7.49:1** | 唯一强调色：当前页指示、链接、主按钮底(`#1f6feb`)、图表主系列、focus 环 |
| 成功 `--ok` | `#3fb950` | 6.81:1 | 错误率 <5% chip、成功 toast、健康状态 |
| 警告 `--warn` | `#d29922` | 6.85:1 | 错误率 5–20% chip、临期/将耗尽、黄 toast |
| 危险 `--err` | `#f85149` | 5.16:1 | 错误率 >20% chip、熔断、红 toast、数据过期 |
| 紫 Reserved `--pur` | `#bc8cff` | 6.86:1 | 仅"智能"域（KB/Agent）语义标识，禁作装饰 |
| chip 底 `--chip` | `#21262d` | — | 中性 chip、输入框底 |
| focus 环 | `rgba(88,166,255,.45)` | — | 输入聚焦 3px 光环 |

### 2.2 亮色主题

| 角色 | HEX | 对比度 | 备注 |
|---|---|---|---|
| 背景 `--bg` | `#f6f8fa` | — | |
| 面板 `--panel` | `#ffffff` | — | |
| 正文 `--fg` | `#1f2328` | 14.84:1 | |
| 次要 `--dim` | `#59636e` | 5.74:1 | |
| 强调 `--accent` | `#0969da` | 4.88:1 | 深蓝压暗保对比度 |
| 成功 `--ok` | `#1a7f37` | 5.08:1 | |
| 警告 `--warn` | `#9a6700` | 4.87:1 | |
| 危险 `--err` | `#d1240f` | 5.29:1 | |
| 紫 `--pur` | `#8250df` | 5.05:1 | |

> **实测结论**：两套主题 18 个关键色对全部 ≥ 4.87:1，满足 WCAG 2.2 AA（正文 4.5:1）。

### 2.3 语义色使用铁律

1. **全站一个口径**：错误率色标由 `rateTone()` 统一（>20% 红 / >5% 黄 / 其余绿），任何页面不得自设阈值——同色同义，降低学习成本。
2. **色不只靠色**：每个状态 chip 自带**状态点 + 文案**（`●` 前缀由 `:before` 渲染），色盲用户可读；错误横幅有标题 + 图标符号。
3. **强调色配额**：一屏之内品牌蓝的大面积使用 ≤ 2 处（当前页指示 + 主按钮），图表系列色用 accent 的透明度梯度而非新色相。
4. **语义色不做交互色**：绿/黄/红永远描述状态，可点击的东西只有 accent 蓝 + 下划线/按钮形。

## 3. 视觉风格

### 3.1 设计语言定位

**"仪表盘式极简"（Instrument-grade minimal）**：GitHub 暗色血统 + 终端/等宽数字文化。层级由**间距、字重、边框**建立，不由投影和渐变建立；装饰性元素（渐变按钮、辉光、插画风空态）一律禁止。这个定位与产品气质一致——它是给相信"字节级透传"的人用的工具。

### 3.2 字体系统

| 用途 | 规格 | 字体栈 |
|---|---|---|
| 正文 | 14px / 1.6 | `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif` |
| 卡片数值 | 23px / 650 / -0.02em | `ui-monospace, SFMono-Regular, Menlo, Consolas` + `tabular-nums` |
| 区块标题 h2 | 13px / 600 | 同正文，前置 3×13px accent 竖条 |
| 表头/标签 | 11px / 600 / 0.04–0.09em | 大写字距拉开（英文字段名） |
| 表体/代码 | 12–13px | 等宽（ID、token、模型名、时间戳、数字一律等宽） |

**规则**：所有数字走等宽 + `tabular-nums`（表格中数字列右对齐）——监控面板数字跳动时不能让整行文字抖动。中文不设 letter-spacing。**禁衬线体**。

### 3.3 图标

当前 v1 用文本符号（◈ ◫ ▤ ◎ 🔑 ⇄ ▣ ✦ ⚙ ⛨），零依赖、跟随文字色。升级路径：若引入视觉资产，统一换 `@phosphor-icons/react`（线性、strokeWidth 1.5 全站统一），**禁止 emoji 混排**（登录页 ⚡ 品牌符保留为例外）。语义色规则同 2.3。

### 3.4 圆角与阴影

| Token | 值 | 用途 |
|---|---|---|
| `--r1` | 6px | 按钮、输入框、chip、导航项 |
| `--r2` | 10px | 卡片、区块、toast、pre、抽屉内表单 |
| `--r3` | 14px | 登录盒、大容器 |
| `--sh1` | `0 1px 2px rgba(0,0,0,.35)` | 卡片级微投影（几乎不可见，只为分层） |
| `--sh2` | `0 10px 30px rgba(0,0,0,.45)` | 浮层专用：抽屉、toast、登录盒 |

**规则**：阴影只表达**悬浮层级**（模态 > 抽屉 > 卡片），卡片默认用 1px 边框分层，不堆投影；圆角不超过三档，禁 pill 形大圆角容器（chip 例外）。

### 3.5 间距与栅格

间距五档：`--s1:4px / --s2:8px / --s3:12px / --s4:16px / --s5:22px`。卡片内边距 s4、区块间距 s3、页面左右 s5。主内容 max-width **1200px** 居中（账本/上游等宽表在 1440+ 显示器上保持可扫读行宽）。

### 3.6 动效规范

| 动效 | 参数 | 用途 |
|---|---|---|
| 微交互过渡 | `120–140ms` | 边框/背景色 hover 变化 |
| 抽屉滑入 | `220ms cubic-bezier(.22,.61,.36,1)` | 右侧详情抽屉、移动端侧栏 |
| 骨架屏扫光 | `1.4s infinite` | 加载占位 |
| 柱状图高度 | `200ms` | 数据刷新时柱高变化 |
| 按压反馈 | `translateY(1px)` | `button:active` 物理下沉感 |

全部动效尊重 `prefers-reduced-motion: reduce`（已实现于侧栏，规则全站适用）。**禁止**：自动轮播、入场大动画、视差。监控面板每 15s 刷数据，动效必须是"变化可感知但不抢注意力"。

## 4. 核心界面设计建议

### 4.1 登录门

```
径向渐变背景（#16273d → bg，聚焦中心）
┌──────────── 392px 白盒 ────────────┐
│ ⚡ api-relay 管理面板               │
│ 说明文案（令牌仅存 localStorage）     │
│ [ 密码输入框           ] ← Enter 提交 │
│ [        登录（pri）      ]          │
│ 错误行（红，17px 高度预留防跳动）      │
│ 网关版本 · 令牌找回说明（dim 小字）    │
└────────────────────────────────────┘
```

**交互要点**：① 进页即预检 `panel-info`，免令牌网关自动登入（登录门不能锁在门里面——ADR-017）；② 连不上给"网关可能未启动"而非裸网络错误；③ Enter 即提交、按钮 busy 态防双击；④ 错误区分"令牌无效"(401) 与"连不上"。

### 4.2 总览（首屏 = 值班台）

信息排序严格执行"**最坏消息优先**"：

```
① statusBanner 状态横幅（条件互斥、按严重度排序）
   无上游 → 全摘除 → 上游拒绝密钥(≥50%失败) → 余额耗尽 → 客户 401(≥50%)
   → 上游错误率突增(≥10次且≥40%) → 无横幅
   每条横幅 = 标题 + 原因 + 「去哪修」链接（跳对应页签）
② 指标卡 grid（请求/失败率/token/成本/p95…）
③ 上游健康横条 HBar + 模型分布
④ 值班摘要（九行结构，可复制全文）
```

**理由**：值班人打开面板的第一个问题是"有没有事"，横幅把"有没有事 + 是谁的锅 + 点哪里"压缩成一次扫视；归因文案写人话（"从网关这边改是没用的——要去厂商控制台检查这个 key"）而非堆错误码。

### 4.3 请求账本（最高频排障页）

```
过滤器行：[状态：全部|失败|成功|…] [模型 ▾] [上游 ▾] [搜索框]     窗口跟随全局
数据表：时间 | 状态chip | 模型(等宽) | 上游 | 延迟ms | token | 耗费
行点击 → 右侧抽屉 580px：
  ├ KV 概览（requestId 可复制）
  ├ 归因卡片：失败原因 + 人话解释 + 建议动作（含 retryAfterMs 等机器可读字段）
  ├ 步骤轨迹（.steps 时间线，✓/✗ 两色）
  └ 原始错误体 pre（等宽、可横滚）
```

**交互要点**：① 行 hover 变 panel2 + cursor 提示可点；② 抽屉打开不卸载列表（上下文保持）；③ 失败原因用全站统一 REASON_HINT 文案，与总览横幅同一套词表——用户在两页看到同一故障的描述必须一致。

### 4.4 客户 Key

```
表：ID | 标签 | 状态chip(启用/禁用/过期/耗尽) | 用量进度条 | 预算 | 过期 | 操作
新建/轮换 → 抽屉表单（label 上置 130px 网格）
轮换成功 → .secret 黄框警示区显示明文（仅此一次）+ 复制按钮
```

**交互要点**：① 明文 key 只在创建/轮换后显示一次，服务端只存 sha256——UI 必须用强视觉（黄边框 + 等宽 + `user-select:all`）强调"现在不存就没了"；② 用量进度条三色阈值与全站口径一致（85%+ 黄、100% 红）；③ 高危操作（禁用/删除）用 danger 按钮 + toast 确认结果，不弹确认框打断（列表可逆操作优先，删除类才二次确认）。

### 4.5 上游

```
上游卡列表：名称 | 健康 chip | 熔断状态(开/半开/闭) | ewma 延迟 | 连续失败 | key 池余量
卡内动作：清熔断 / 摘除 / 恢复启用 / 编辑
```

**交互要点**：① 熔断打开 = 红 chip + 明确"冷却剩余时间"；② **清熔断是廉价操作**（一次点击 + toast），鼓励充值后立即恢复；③ 全部上游摘除时页顶横幅警示"请求无处可去"（与总览同文案）。

### 4.6 排障 / 运维

事件日志表：时间 | 级别 chip | 事件 | 详情展开。配置区写操作**每次都进事件流**（留痕即审计）——UI 上"保存成功" toast 与事件流新增一行同时发生，用户可以互相印证。

### 4.7 六态规范（全站组件状态清单）

| 态 | 规范 | 实现 |
|---|---|---|
| 默认 | 主操作按钮 pri 蓝可见；空过滤器不隐藏数据 | ✓ |
| 加载 | **骨架屏**（按目标布局 1:1 占位，扫光动画），禁止裸 spinner | `.skel` ✓ |
| 成功 | toast 绿色 4.2s + 下一步引导文案（"已复制""已清熔断，观察 1 分钟"） | ✓ |
| 错误 | 分类文案：输入/状态问题(4xx)=黄"未完成+怎么改"；系统故障(5xx/网络)=红；错误行内展示，表单不清空已填内容 | `writeErr()` ✓ |
| 空态 | `.empty` 居中：**解释为何为空 + 行动入口**（"窗口内无请求——发一个试试"），配 22px 淡图标，禁止纯插图 | ✓ |
| 禁用 | 按钮 45% 透明 + `cursor:not-allowed`；busy 时文案不变但不可点，防双击 | ✓ |

## 5. 可用性检查清单（尼尔森启发式逐项）

| # | 启发式 | 结论 | 依据/修复 |
|---|---|---|---|
| 1 | 系统状态可见 | ✅ | 数据新鲜度 60s 变红；toast 分级；自动刷新可关 |
| 2 | 贴近真实世界 | ✅ | 归因文案人话 + 动作建议；中英文按域混排符合开发者习惯 |
| 3 | 用户控制与自由 | ✅ | 抽屉/scrim/Esc 关闭；切换页签不丢滚动；登出即清 token |
| 4 | 一致性与标准 | ✅ | 同色同义（rateTone 全站唯一）；同构页面同构布局（§1.3 公式） |
| 5 | 错误预防 | ✅ | 表单 label 上置 + 行内错误；高危操作独立 danger 样式；窗口控件沉底防误触 |
| 6 | 识别而非回忆 | ✅ | 当前页高亮 + 左缘条；过滤器状态在 chip 上可见 |
