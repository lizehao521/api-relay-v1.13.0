## 2. 问题清单（P0–P3）

### P0-1 · 交付环境未注入任何凭据，真实上游成功链路不可验证
- **现象**：`OPENCSG_API_KEY_1/2/3`、`RELAY_ADMIN_TOKEN`、`RELAY_KEY_FREE/STANDARD/PRO/AGENT`、`RELAY_ADMIN_PASSWORD`、`RELAY_VIEWER_PASSWORD` 在**进程级 / User 级 / Machine 级**环境变量中全部不存在；`docs/HANDOVER-20260914.md:204` 所述"唯一副本 `.relay-net.env`"在包内不存在；包内无 `.env`。
- **影响**：`npm run check` 报 15 项告警；`serve` 按当前 `config/relay.yaml`（`{ENV:...}` 无默认值）会**直接装载失败**；任何 fresh-clone 的验收者无法启动网关，也无法复现"真实上游成功"这一条验收项。本轮 T4 只能验证到上游 401。
- **根因**：交付打包时密钥按安全约定排除，但**没有同时提供可运行的替代凭据路径**（`relay.example.yaml` 有 `:-demo` 兜底，主配置没有）。
- **修复**：① 交付说明里给出 `npm run demo`（mock 上游，零密钥）作为默认验收路径，并把"真实上游"列为需外部注入的可选门禁；② 为 `config/relay.yaml` 的 `clients[].key` 增加 `:-` 兜底或提供 `config/relay.verify.yaml`；③ 若要求真实上游验收，随包提供一次性只读 key 或在 CI 里以 secret 注入并打印 `relay check` 通过证据。
- **验收标准**：干净目录 `npm ci && npm run build && npm run demo` 可跑通；或注入 key 后 `POST /v1/chat/completions` 返回 200 且 `relay.db` 有成功记账。

### P1-1 · `/v1/messages` 在 Anthropic 入站适配关闭时被放行并按 OpenAI 语义处理（静默错误语义）
- **位置**：`src/gateway/server.ts:374-383`。`inbound?.anthropic` 为 opt-in 且缺省关闭（`config/relay.yaml` 内**不存在** `server.inboundAdapters`），但 `supported` 数组把 `/v1/messages` **硬编码**为支持端点。
- **证据**：本轮以 Anthropic 契约（`{model, max_tokens, messages:[{role,content:[{type:'text',…}]}]}` + `anthropic-version` 头）请求 `/v1/messages`，返回 **503 并真实出网 1 次**，而不是"适配未开启"的显式错误 —— 说明请求进入了 OpenAI 主链路。
- **影响**：① Anthropic 顶层 `system` 字段被忽略 → **系统提示静默丢失**；② `content` 块数组（image/tool_use）未按 `anthropicToOpenAI` 校验，可能透传畸形 body 给上游；③ 响应以 OpenAI 形状返回，Anthropic SDK 解析失败；④ 消耗上游配额。与项目自身原则冲突（`e2e: Anthropic 入站适配：流式显式 400（不静默降级）`、`不支持字段显式 400`）。
- **修复（最小改动）**：`supported` 按开关动态生成 —— `inbound?.anthropic` 为假时不列入 `/v1/messages`，从而落到既有 404 分支，并在 message 里追加处置指引：`Anthropic 入站适配未开启，请设置 server.inboundAdapters.anthropic: true`。
- **验收标准**：新增 e2e 用例 —— 关闭开关时 `POST /v1/messages` → 404 `unknown_endpoint` 且 message 含 `inboundAdapters.anthropic`，**上游调用计数为 0**；开启开关时行为与现有 anthropic e2e 一致。

### P1-2 · 交付包内 frontend 依赖不完整，T1 两项门禁不可运行
- **现象**：`npm --prefix frontend run lint` → `'eslint' is not recognized`（EXIT=1）；`npm --prefix frontend run smoke` → `ERR_MODULE_NOT_FOUND: puppeteer-core`（EXIT=1）。`frontend/node_modules` 缺 113 个包（`eslint`、`puppeteer-core` 等）。
- **影响**：静态门禁的 lint / smoke 两项在交付状态下**默认不可执行**，而 smoke 恰是 P0-2 线上事故（TDZ 伪装成"网络不可达"）的唯一回归门 —— 门禁缺失等于事故防线缺失。
- **修复**：① 文档与 `scripts/ops-check.sh` 增加 `npm --prefix frontend ci` 前置步骤；② `check` 脚本里对 lint/smoke 做**依赖存在性预检**，缺失时以明确错误退出（而不是命令找不到）；③ 交付包内附 `frontend/node_modules` 或安装校验清单。
- **验收标准**：干净检出下 `npm run check` 能报出"frontend 依赖缺失"并给出可执行修复命令。

### P2-1 · 性能基线门禁红灯：`dimensionStats(24h,"provider_id")` 稳定超预算
- **证据**：`npm run bench` 两次实测 **220.4ms / 203.4ms**，预算 **200ms** → **EXIT=1**（其余 5 项 PASS：62.2 / 64.4 / 59.6 / 225.2 / 42.4ms）。
- **影响**：`bench` 是 C-05（每桶 p95 全扫 1.2s）的回归钉，红灯会让 CI 无法把它作为门禁；node:sqlite 为同步 API，该耗时即事件循环冻结时长，管理面并发下会放大。
- **修复**：二选一并说明口径 —— ① 按 `provider_id` 走已有索引/物化聚合（与 `model` 维度同实现）；② 若 200ms 预算过紧，在 `BUDGET_MS` 上调并附实测依据（不得静默放宽到掩盖回归）。
- **验收标准**：`node scripts/bench.mjs` 退出码 0，且连续 3 次运行 `provider_id` 维度有 ≥15% 余量。

### P2-2 · CLI 失败形态不一致：`catalog` / `report` 抛未捕获错误并泄露绝对路径
- **证据**：缺 `RELAY_ADMIN_TOKEN` 时 `node dist/cli.js catalog|report` 输出 `未捕获错误: Error: … ` + 8 层 stack（含 URL 编码的本地绝对路径），EXIT=1；同一条件下 `check` 输出结构化告警清单且 EXIT=0。
- **影响**：与项目自述"错误可执行"主张冲突；用户拿不到"下一步做什么"；stack 里的绝对路径对终端用户无价值、对日志采集是噪声。
- **修复**：`loadWithOverrides()` 的配置装载异常在 CLI 顶层统一捕获，打印 `缺哪些环境变量 + 一条 export 示例`（复用 `check` 的告警渲染），仅在 `--debug` 下输出 stack。
- **验收标准**：清空环境变量执行 `catalog/report`，输出不含 `at file:///`，且包含可执行指引与缺失变量名。

### P2-3 · 仓库根调试脚本 `verify_admin.mjs` 已失效（运行时崩溃）
- **证据**：`node verify_admin.mjs` → `TypeError: Cannot read properties of undefined (reading 'info')`，位置 `dist/mock/upstream.js:48`。根因：`MockUpstreamOptions.logger` 为**必填**（`src/mock/upstream.ts:44`），而脚本第 10 行 `new MockUpstream({ port: 0 })` 未传。
- **影响**：脚本自称"e2e 失败根因定位"，如今自身即失败；TS 类型检查覆盖不到 `.mjs`，任何门禁都不会发现 → 排障时会误导使用者。
- **修复**：① 补 `logger`（或让 `MockUpstream` 内部对缺省 logger 兜底为静默 logger，从根上消除该类崩溃）；② 若脚本已完成历史使命，删除并移入 `docs/` 归档。
- **验收标准**：脚本退出码 0 且打印 5 项断言结果；或被删除。

### P2-4 · 凭据级 fatal 熔断后对外语义降级为 503，诱导客户端无效重试
- **证据**：三 provider 因 `auth_invalid` 各 1 次失败即熔断（`src/upstream/pool.ts:292` `if (fatal || …)`），后续请求返回 **503 + `retry_after_ms=30000`**，而归因 `next=fix_credentials;recoverable=false`。
- **影响**：客户端按 503/`Retry-After` 语义会退避重试一个**永不成功**的请求，正是 ADR"预算用尽必须返回 402 而不是 429（别让客户端无效重试）"要消除的同类问题，但熔断路径未被同一原则覆盖。
- **修复**：当 `openBreakers` 的根因全为 fatal 凭据类（`auth_invalid` / `quota_exhausted`）时，状态码取 **401 / 402** 而非 503，并且**不下发 `Retry-After`**；仅当根因为过载类（rate_limited/timeout/5xx）才保留 503 + 冷却提示。
- **验收标准**：新增 e2e —— 单 provider + 上游 401 → 第二次请求得到 401（非 503）且无 `retry-after` 头；上游 429 → 仍为 503 + `retry-after`。

### P3-1 · 运维 shell 脚本本轮不可执行（覆盖缺口）
`demo.sh`、`start-net.sh`、`scripts/{smoke.sh,ops-check.sh,keepalive.sh,watch.sh,db_backup.sh,ddns-dynv6.sh,setup-v6-tls.sh,start-tunnel.sh,start-funnel.sh,dashboard-record.sh}` 共 12 个 bash 脚本在 Windows 环境无法执行，T3 未覆盖。建议：为关键脚本补 `.mjs` 等价实现（跨平台），或在 `README` 标注"仅 Linux/macOS"。

### P3-2 · smoke 正文长度阈值偏低
`frontend/scripts/smoke-render.mjs:23` `MIN_LEN=200`，而实测 `kb=404`、`agentchat=363`、`agent=679` 接近阈值，空数据态与渲染失败难区分。建议按页签设差异化阈值，并追加"必须出现关键 DOM 锚点"断言（而非仅长度）。

### P3-3 · 生成物行尾在 Windows 下抖动（LF↔CRLF）
`npm run config:build` 重跑后内容逐字节一致（`relay-net.yaml` 与 `config/relay.yaml` SHA256 相同、幂等 ✓），但 git 报警 `LF will be replaced by CRLF the next time Git touches it`，跨平台 checkout 会制造整文件伪 diff（`--stat` 640 行）。建议：加 `.gitattributes`（`*.yaml text eol=lf`、`*.ts text eol=lf`）。

### P3-4 · CLI 中文输出在 PowerShell/GBK 下乱码，影响 CI 采集
多条命令输出无法按 UTF-8 读取（需 `*>` 落盘 + `-Encoding UTF8` 才可用）。建议：门禁类命令统一支持 `--json` 并以 UTF-8 无 BOM 输出，CI 只消费 JSON。

## 4. 假设与风险

- **假设 1**：用户所述"key 已注入"指交付前在部署机上注入；本机三级环境均无该变量，故本轮以占位密钥完成运行链路验证，真实上游仅验证到 401。**成功链路（200 + 记账）仍是未验证项。**
- **假设 2**：`--host 127.0.0.1` 覆盖配置内 `0.0.0.0`，避免验证期间把带 `hideUpstream` 的管理面暴露到局域网。
- **风险 1**：P1-1（`/v1/messages` 放行）在生产上会造成 Anthropic 客户端**系统提示静默丢失**，属数据可信类缺陷，建议优先于性能项修复。
- **风险 2**：P1-2 使 smoke/lint 在验收环境默认不可跑，事故回归门形同虚设。
- **风险 3**：本轮 `data/relay.db` 被探针写入若干 401/503 记账，若交付截图/报告直接引用该库，会出现"验证期噪声数据"。

## 5. 建议修复批次（按优先级）

- **批次 A（P0/P1）**：真实凭据注入路径 + `supported` 端点按 `inboundAdapters` 动态生成（含 e2e 用例） + frontend 依赖预检。
- **批次 B（P2）**：`bench` provider_id 维度性能修复；CLI 顶层异常统一渲染；`verify_admin.mjs` 修复或归档；fatal 熔断状态码语义（401/402 + 去掉 `Retry-After`）。
- **批次 C（P3）**：`.gitattributes` 行尾策略；shell 脚本跨平台化；smoke 差异化阈值 + DOM 锚点断言；门禁命令 `--json` 化。

每批完成后复跑：`npm run check` → `npm run build` → `npm test` → `npm run e2e` → `npm run bench` → `npm --prefix frontend run smoke`。
