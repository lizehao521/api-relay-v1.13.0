## §3 问题清单（P0 / P1 / P2）

### P0（阻断）
**无。P0 = 0。**

### P1（落地前需完成，≤3 通过）
- **P1-1 接口/类型精确对齐**：新增端点（`/agent/connectors*`、`/agent/apply*`、`/agent/metrics/trend`、`/agent/eval*`、`/agent/team*`）需并入 `src/admin/api.ts` 路由表与 `src/admin/handlers/agent.ts`，并复用 `numParam` 边界校验。
- **P1-2 新表迁移与 prune**：`agent_run`/`agent_apply`/`agent_connector_call` 建表 + 迁移 + 纳入 `store.prune`（保留期对齐 `meter.retentionDays`）。
- **P1-3 保险丝双保险**：`apply` 执行前必须二次校验白名单（不信任上游 payload）+ `confirmToken`，并在执行/回滚全程写事件。
- **P1-4 多实例租约语义**：现有 `InstanceLease` 为"事件表打标 + TTL"，方案设想的"仅 leader 跑"需评估其在并发下的强一致边界（保留现状或升级，二者择一并记录）。

### P2（可选优化）
- **P2-1** query 参数命名与现有 `?limit/?open` 风格统一；`cursor` 分页格式与既有对齐。
- **P2-2** 执行白名单常量与 `runner.ts` `PROPOSED_CHANGE_TARGETS` **单一来源**（避免双份漂移）。
- **P2-3** `/agent/metrics/trend` 载荷天花板（沿用 `#353` 教训，做上限与下采样）。
- **P2-4** 连接器响应脱敏规则的词表化（可维护）。
