### 0.3 设计令牌消费规则（转述 02 文档，强制）

1. **只用令牌，不写死值**：任何色/尺寸必须能在 02 文档找到 `--xxx`（02 §A 落地顺序 B1）。
2. **暗色优先、双主题同源**：`data-theme="dark"`（默认）/ `"light"`；不为亮色单独写组件样式。
3. **数字列三件套**：`tabular-nums` + 右对齐（`.num`）+ 等宽字体（`--font-mono`）。
4. **双面密度**：运营面 `data-density="compact"`、客户面 `data-density="cozy"`。
5. **零依赖**：图标仅文本符号/内联 SVG；字体仅系统栈；禁止任何 CDN/`@import url()`。
6. **状态四态齐全**：`ok/warn/danger/info` + `neutral` 兜底，且**色 + 符号**双编码。
7. **红线不可暗示**：不得暗示改写成功响应/缓存/去重/Agent 平台能力；`X-Relay-Mode` 类透明信息应可见。

- **目标**：锚定本轮交付边界与页面清单，让审查官一眼知道"原型应该有什么、不该有什么"。
- **输入**：阶段1 §2.3（交付定位）、§5.4（N1–N10）、§附录 B（页面优先级）；阶段2 §A/B（令牌落地顺序与 7 条要点）。
- **产出物**：§0.1 定位、§0.2 页面清单、§0.3 令牌消费规则。
- **关键决策**：① 按阶段1 §附录 B 的 P0 优先，原型**必做** 11 个新增/改造页；② 保留页（met/ch/ledger/diag/ops/trust）以"令牌迁移"方式纳入 IA，不重画；③ 把 N6「事故处置聚合」并入「路由策略配置」页，避免页面膨胀。

## 1. 页面结构与信息架构

### 1.1 双面站点地图（Tree）

平台物理上只有一个 `/admin` 入口（阶段1 §7 Q5 默认：**暂不独立域名**），但**逻辑上分两面**：运营面（`role=admin|sre|finance|auditor`）与客户面（`role=client`）。两面共享同一套令牌与组件，通过 `data-density` 与信息显隐、以及登录态决定导航可见性。

```text
api-relay /admin
├─ #/login                          登录门（保留，双重身份：运营令牌 / 客户令牌）
│
├─ 【运营面】data-density="compact"  可见角色: owner / sre / finance / auditor
│  ├─ 值守
│  │  ├─ #/ov            总览（改造：新增毛利速览 + 事故横幅聚合）
│  │  ├─ #/met           指标（保留 · 令牌迁移）
│  │  ├─ #/ledger        请求账本（保留 · 令牌迁移）
│  │  └─ #/diag          排障（保留 · 令牌迁移）
│  ├─ 经营
│  │  ├─ #/users         客户与租户管理（改造：由「客户 Key」升级，加租户维度）
│  │  ├─ #/approvals     密钥审批队列（新增 N3）★
│  │  ├─ #/plans         套餐目录（运营视角，新增 N1）★
│  │  ├─ #/route         路由策略配置（新增，吸收 N6）★
│  │  ├─ #/ch            上游（保留 · 令牌迁移）
│  │  ├─ #/billing       计费与对账（新增 N4/N5）★
│  │  └─ #/observ        可观测看板（新增 N9，SLO/告警/时间线）★
│  └─ 系统
│     ├─ #/ops           运维（改造：剥离内部工程能力到「高级」折叠区）
│     ├─ #/trust         信任（保留 · 令牌迁移）
│     ├─ #/audit         审计日志（新增 N8）★
│     └─ #/agent         知识库/Agent（内部位，标记为"内部支撑，非对外卖点"）
│

   ├─ #/plans           套餐目录 / 定价（客户视角，新增 N1）★
   ├─ #/docs            API 文档 / 快速开始（新增 N7）★
   └─ #/status          状态页 / 可用性（新增 N7/N9）★

★ = 本文 §3 详述的重点页
```

> **同名页不同视角**：`#/plans` 在运营面是"管理在售套餐"，在客户面是"选购套餐"，用 `role` 决定渲染分支（同一路由，两个视图组件）。这点是 IA 的关键——避免为两面各造一个 URL 造成认知分裂。

### 1.2 导航分组（重排为"值守 → 经营 → 客户 → 系统"）

沿用阶段2 §6.2 的四组重排建议，落地为运营面侧栏：

| 分组（group label） | 运营面页签 | 定位 |
|---|---|---|
| **值守** | 总览 `ov` · 指标 `met` · 请求账本 `ledger` · 排障 `diag` | 值班/监控核心（原"监控"改名） |
| **经营** | 客户与租户 `users` · 密钥审批 `approvals` · 套餐目录 `plans` · 路由策略 `route` · 上游 `ch` · 计费对账 `billing` · 可观测 `observ` | 钱与配置（原"配置"扩展） |
| **客户** | 客户门户预览 `portal-preview` | 对外客户面入口（管理员可预览客户视角） |
| **系统** | 运维 `ops` · 信任 `trust` · 审计 `audit` · 内部 Agent | 平台与治理 |

**客户面侧栏**（`role=client` 时整体替换）：

| 分组 | 客户面页签 |
|---|---|
| **我的** | 控制台概览 `portal` · 我的密钥 `keys` · 用量与账单 `usage` |

> **迁移提示**：分组重排会改变用户肌肉记忆（阶段2 §6.4 风险①），原型在 `#/ov` 首次进入时用一条可关闭的 `note` 提示"导航已重排"，并提供"按旧顺序查看"开关（仅运营面）。

### 1.4 面包屑与抽屉层级

**面包屑**（运营面较深）：主内容区顶部一行 `分组 › 页面 [› 详情]`，字号 `--fs-xs`、色 `--c-fg-muted`，最后一级为当前面（`--c-fg`）。示例：`经营 › 计费与对账 › 客户 acme-corp 账单`。

**抽屉层级**（沿用阶段2 §5.4）：

| 层级 | 形态 | 示例 |
|---|---|---|
| L1 列表 | 表格主视图 | 密钥审批队列 |
| L2 抽屉 | 右侧 `--drawer-w` 详情/表单 | 审批详情、Key 编辑 |
| L3 抽屉内子区 | 抽屉内折叠/内嵌卡片 | 审批记录时间线、路由阶梯预览 |
| L4 二次确认 | 抽屉内 `role=alertdialog` 内联确认条 | 轮换 key、批量停用 |

> **原则**：**不叠第二层抽屉**（线性堆叠会遮蔽上下文）；需要"从抽屉再开详情"时，改为抽屉内**分区折叠**或**锚点跳转**。不可逆动作集中在抽屉，且后果写在按钮**之前**（阶段1 §1.3）。

### 1.5 新增 / 改造 / 保留 标注（对照阶段1 §1.4 复用判断）

| 判断 | 阶段1 结论 | 阶段3 处置 |
|---|---|---|
| **保留** | 总览、指标、上游、请求账本、排障、信任（7 项中 6 项纯保留） | 仅做令牌迁移，视觉对齐；结构不动 |
| **改造** | 客户 Key（钱包/审批子域）、运维（剥离内部能力）、Agent/知识库（评估移出） | 客户 Key → 「客户与租户管理」+ 独立「密钥审批队列」；运维页把内部工程能力收进"高级（折叠）"；Agent/知识库标注"内部支撑，客户面不出现" |
| **新增** | N1 套餐目录 / N2 客户自助门户 / N3 审批队列 / N4 用量账单 / N5 成本毛利 / N6 事故处置 / N7 开发者文档 / N8 审计合规 / N9 告警态势 / N10 多租户 | 落地为 §0.2 的 11 个重点页；N6 并入 `#/route`；N10 以 `tenantId` 维度落进 `#/users` 与客户面过滤 |
| **不出现** | 知识库/Agent/Agent 对话 作为对外卖点 | 客户面**绝不**出现这三页（阶段1 §7 Q11 默认：不对外） |

### 1.6 本部分元信息

- **目标**：把"双面平台"的空间结构定死——谁看到哪些页、页在 URL 上长什么样、层级如何表达。
- **输入**：阶段1 §1.1/§1.4/§5.1/§5.4/§附录 B；阶段2 §6.0–§6.4（壳层/导航/路由/分组）。
- **产出物**：§1.1 站点地图、§1.2 导航分组、§1.3 路由映射表、§1.4 面包屑/抽屉层级、§1.5 增改留标注。
- **关键决策**：① **单入口双面**（不独立域名），用 `role` + `data-density` 分面；② 同名页 `plans` 双视角；③ **禁止抽屉套抽屉**；④ 客户面**绝不出现** Agent/知识库。
- **风险与待办**：① 分组重排需一次性提示（保留旧顺序开关）；② `role` 在现状只有单一 `X-Admin-Token`（阶段1 §3 风险①）——原型仅表达，落地需后端；③ 面包屑在保留页（无分组深度）可省略。

#### 3.A.1 开发者控制台概览 `#/portal`（N2 · P0）

- **目标**：客户登录后 5 秒内回答"我的 key 能用吗、我这个月花了多少、还差多少到预算、最近有没有报错"。
- **角色**：`client`（只读 + 跳转自助）。
- **布局**：Banner（预算预警，可选）→ KPI 4 列 → 主从两栏（左 1.3fr：近 24h 用量迷你柱图 + 最近请求摘要；右 1fr：密钥卡 + 套餐卡 + 快速开始卡）。
- **主要模块**：
  1. **欢迎条**：`tenantId` 名称 + 当前套餐 `.tier-*` chip + "看板数据新鲜度"。
  2. **KPI Tiles（4）**：本周期 Token / 本周期成本(¥) / 预算余额(¥) / 请求成功率。
  3. **用量迷你柱图**：近 24h 按小时的 `tokens`（可切 5m/1h/24h 窗口，联动 `--dur-bar` 过渡）。
  4. **密钥卡**：脱敏 key（`sk-relay-••••••••` + 指纹后 8 位）+ 状态 chip + "查看/轮换"入口 → `#/keys`。
  5. **套餐卡**：当前套餐名 + 圈定模型数 + 剩余预算 MiniBar + "升级套餐" → `#/plans`。
  6. **快速开始卡**：两行 SDK 代码片段（`base_url` + `api_key`）+ 复制按钮 → `#/docs`。

- **字段表（KPI）**：

| 字段 | 类型 | 说明 | 令牌/格式 |
|---|---|---|---|
| `periodLabel` | string | 本计费周期，如 `2026-10-01 ~ 2026-10-30` | `--fs-xs` `--c-fg-muted` |
| `tokensUsed` | number | 本周期 token 用量 | `.num` `--fs-2xl` `--fw-kpi` |
| `costCny` | number | 本周期实付成本 | `cny()` → `¥x.xxxx` |
| `quotaCny` / `quotaCnyUsedPct` | number | 预算与占用比 | MiniBar 阈值 >90%红 >70%黄 |
| `quotaCnyRemain` | number | 预算余额 | 右对齐等宽 |
| `successRate` | number | 成功率 = 1 - errRate | `pct()`，`rateTone` 上色 |

- **主操作**：`查看密钥`（→`#/keys`）· `升级套餐`（→`#/plans`）· `查看完整账单`（→`#/usage`）。
- **次操作**：窗口切换（5m/1h/24h）· 复制快速开始代码 · 主题切换。
- **空态**：无密钥 → `Empty(icon="⚑", "还没有可用的密钥", "点击『我的密钥』申请一把")`，KPI 显示 `—`（**不编造数字**）。
- **加载态**：KPI + 图表用骨架屏（§5.10）；首载必用。
- **错误态**：单区块降级——若 `/v1/quota` 失败，KPI 区显示 `note.warn` "用量数据暂时不可用（不影响调用）"，其余区块照常（fail-open 展示策略）。
- **权限门**：`role=client` 可见；`tenantId` 缺失 → 显示 `note` "账号未绑定租户，请联系运营"。

#### 3.A.2 我的密钥 `#/keys`（N2/N3 · P0）

- **目标**：客户**自助**完成"申请 → 查看 → 自检 → 轮换"，无需联系运营（阶段1 场景1/场景5）。
- **角色**：`client`。
- **布局**：顶部动作条（`申请新密钥` 主按钮 + 粘贴自检输入区）→ 密钥表格 → 右侧抽屉（一次性明文 / 申请表单 / 轮换确认）。
- **主要模块**：
  1. **粘贴自检区（whoami 客户版）**：一个输入框 + `自检` 按钮，服务端换算指纹后返回四态结论。**明文不写日志、不落盘、不进台账**（README §8）。
  2. **密钥表格**：列 `备注 / 指纹 / 状态 / 套餐 / 模型数 / 额度 / 预算 / 到期 / 操作`。
  3. **一次性明文抽屉**：新签发/轮换后弹出，明文**只显示一次**，配"已记下/复制"确认。
  4. **申请抽屉**：选择套餐 → 选择期望模型白名单（受套餐圈定）→ 用途备注 → 提交申请单（进审批队列）。
  5. **轮换两步确认**：抽屉内先"生成新 key"→ 再"确认旧 key 立即失效"。

- **字段表（密钥行）**：

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `id` | string | key 短 id | `keys` |
| `label` | string | 备注（如 "生产-主"） | `keys` |
| `fingerprint` | string | `sha256("relay-key:"+key)` 前 8 位十六进制 | 只展示指纹，永不回显明文 |
| `enabled` | bool | 启用/停用 | `keys` |
| `tier` | enum | `free/standard/pro` | chip `.tier-*` |
| `allowedModels` | string[] | 白名单（套餐圈定） | `keys` |
| `quota` / `quotaUsedPct` | number | token 额度与占用 | MiniBar |
| `quotaCny` / `quotaCnyUsedPct` | number | 预算¥ 与占用 | MiniBar（超 100% → `已用完` chip `.r`） |
| `expiresAt` | ts | 到期时间（≤7 天 → `.y` 将过期） | `keyState()` |
| `attention` | bool | 需关注（过期/将尽/用完） | `keyState()` |

- **状态 chip（keyState 口径，沿用 ui.tsx）**：`生效中`(.g) / `将过期`(.y) / `已过期`(.r) / `已用完`(.r) / `将耗尽`(.y) / `已停用`(.n) / `待审批`(.b)。
- **主操作**：`申请新密钥` · `粘贴自检` · 单行 `查看详情`。
- **次操作**：`轮换`（抽屉，两步）· `停用/启用` · `复制指纹` · 导出（CSV/JSON，客户仅自己）。
- **空态**：`Empty(icon="⚑", "还没有密钥", "点『申请新密钥』→ 选择套餐 → 提交，运营审批后签发")`。
- **加载态**：表格骨架屏 5 行；自检为**行内** loading（按钮转 `…`，禁用重复点击）。
- **错误态**：
  - 自检四结论：`有效`(.g) / `已禁用`(.r) / `已过期`(.r) / `不是本网关当前签发的`(.n)——**色 + 文字**双编码，且明确"下一步做什么"。
  - 提交申请失败 → Toast `.r`；重复提交（同套餐同用途）→ `409` → Toast `.y` "已有待审批的相同申请"。
- **权限门**：`role=client`。**明文只显示一次**：抽屉关闭后再点"查看"只显示指纹 + "明文不提供回显，忘了请轮换"。

#### 3.A.3 用量与账单 `#/usage`（N2/N4 · P0）

- **目标**：客户自助查"本周期用了多少、花了多少、账单口径是什么"，并导出对账单（阶段1 场景4 客户侧）。
- **角色**：`client`。
- **布局**：周期选择器（`本周期` / `上月` / 自定义区间）→ KPI 3 列（Token / 成本 / 预算占用）→ 主从两栏（左：按模型用量表；右：预算 MiniBar + 计费口径说明卡）→ 底部：账单明细表 + 导出条。
- **主要模块**：
  1. **周期选择器**：`<select>` 或日期区间；切换重拉。
  2. **KPI 3 列**：Token / 成本(¥) / 预算占用（MiniBar）。
  3. **按模型用量表**：`模型 / 请求数 / 输入token / 输出token / 成本¥ / 占比`（右对齐等宽，占比用 HBar）。
  4. **计费口径卡**：说明 `额度(token)` vs `预算(¥)` 两个独立口径（README §8）、币种 ¥、周期默认 30 天（阶段1 §7 Q4）。
  5. **账单明细表**：`日期 / 模型 / 请求数 / token / 成本¥ / 累计¥`。
  6. **导出条**：`导出对账单 CSV`（BOM + CRLF，Excel 直开）/ `导出 JSON`。

- **字段表**：见上；金额一律 `cny()`、token 用 `formatNumber`、比率 `pct()`。
- **主操作**：`导出对账单 CSV` · `导出 JSON`。
- **次操作**：周期切换 · 按模型排序 · 复制账单摘要。
- **空态**：周期内零用量 → `Empty(icon="▤", "本周期暂无用量", "发起一次调用后这里会出现明细")`。
- **加载态**：表格 + KPI 骨架屏；导出按钮进入 `导出中…` 禁用态。
- **错误态**：区间非法（起>止）→ 行内红字提示（`--c-danger`）；超长区间 → `note.warn` "区间超过 90 天，仅展示汇总"。
- **权限门**：`role=client`（仅自己 `tenantId`）；未绑定租户 → 空态提示联系运营。

#### 3.A.4 套餐目录 / 定价 `#/plans`（客户视角，N1 · P0）

- **次操作**：切换计费周期展示（月/季）· 展开模型矩阵 · 复制套餐摘要。

#### 3.A.5 API 文档 / 快速开始 `#/docs`（N7 · P1）

- **目标**：客户拿 key 即用——一页给出 `base_url`、SDK 示例、端点表、错误码表、自验命令（Trust 素材系统化，阶段1 §2.2「客户语言」）。
- **角色**：`client`。
- **布局**：三栏（左 目录 TOC 粘性 / 中 正文 / 右 "在此页"锚点）——`docs-page` 模板；≤960px 折为单栏 + 顶部目录折叠。
- **主要模块**：
  1. **快速开始**：3 步（改 `base_url` → 缓冲 `api_key` → 发一次请求），每步配代码块（`--c-surface-code` 底）。
  2. **SDK 示例**：OpenAI SDK（Python/Node）只改两行 + `auto-retry.ts` 一行封装（README §7.5）。
  3. **端点表**：`/v1/chat/completions`（含 SSE）· `/v1/completions` · `/v1/embeddings` · `/v1/models` · `/v1/responses` · `/v1/messages` · `/v1/quota` · `/v1/attribution/catalog`。
  4. **错误码表**：`401 / 402 / 403 / 404 / 429 / 502 / 503` + 归因 `failure_reason` 与 `quick_action` 对照。
  5. **自验命令**：`x-relay-verify-nonce` → `x-relay-content-hmac` 对拍（README §8 三条产品原则①）。
  6. **模型清单**：`GET /v1/models` 实时结果 + 阶梯名说明。

- **字段表（端点行）**：`方法 / 路径 / 说明 / 是否流式 / 备注`。
- **字段表（错误码行）**：`HTTP / failure_reason / quick_action / recoverable / 客户该做什么`。
- **主操作**：`复制代码` · `复制 curl`。
- **次操作**：语言切换（Python/Node/curl）· TOC 跳转 · 主题切换。
- **空态**：不适用（静态内容）；`/v1/models` 拉取失败 → 区块内 `note.warn` "模型清单加载失败，稍后重试"。

## 4. 关键交互（≥12 条）

> 每条按 **触发 → 反馈 → 边界** 描述；边界含"失败/并发/权限/无障碍"四种情况。

### I1 · 新建 Key 的一次性明文抽屉（§3.B.3 / §3.A.2）

- **触发**：运营在审批队列点"批准并签发"，或客户在 `#/keys` 提交申请被批准后。
- **反馈**：抽屉（E3, z-60）滑入，正文为**一次性明文**（等宽、`--c-surface-code` 底）+ 指纹 + 复制按钮 + 客户接入包（`customerPackage`）。底部动作：`我已记录明文`（关闭）。
- **边界**：
  - 关闭后**再不可查看明文**（再次点击只显示指纹 + "忘了请轮换"）。
  - 复制走 `copyText`（失败降级 `execCommand`，再失败 Toast `.y`）。
  - 不落正文/不写日志（服务端只存 sha256）。
  - 无障碍：抽屉 `role=dialog aria-modal=true`；打开焦点入标题；`Esc` 关闭并**归还焦点**到触发按钮。

### I2 · 轮换 Key 的两步确认（§3.A.2 / §3.B.2）

- **触发**：`更多…` 抽屉点"轮换"。
- **反馈**：第一步生成新 key（显示新指纹）；第二步内联确认条警告"旧 key **立即失效**"，需勾选"我知道旧 key 会立即失效"才可点确认（不可逆动作后果写在按钮前）。
- **边界**：
  - 未勾选 → 确认按钮 `disabled`（45% 不透明）。
  - 旧 key 正在被使用的提示（"使用旧 key 的客户端会收到 401，请先切换"）。
  - 并发：若旧 key 已被他人轮换 → `409` → Toast `.y`。

### I3 · 审批流状态流转（§3.B.3）

- **触发**：owner 在审批抽屉点"批准并签发"/"拒绝"/"部分批准"。
- **反馈**：状态 chip 从 `待处理`(.b) → `已批准`(.g) / `已拒绝`(.r) / `部分批准`(.y)；抽屉内**审批记录时间线**追加一步（actor+时间+备注）；待处理计数徽标 `N` 减一。
- **边界**：
  - 拒绝**必填理由**（否则按钮 disabled）。
  - 部分批准**必须**改至少一个条件（白名单或预算）。
  - 并发双审 → 后到者 `409` "该申请已被处理"，UI 刷新状态。
  - 权限：`sre` 只能初审/备注，批准按钮 disabled + tooltip。

### I4 · 用量图窗口联动（§3.A.1 / §3.B.6 / 保留页 met）

- **触发**：切换窗口 `5m / 1h / 24h / 7d`（`<select>` 或按钮组）。
- **反馈**：所有图表 + KPI + 表格**同步重拉**；桶粒度映射（5m→60s / 1h→300s / 24h→3600s / 7d→86400s，沿用 `setWindow`）；柱图高度用 `--dur-bar`(200ms) 过渡。
- **边界**：
  - 切换时旧数据**保留**（骨架屏覆盖），避免闪空。
  - 请求未返回前禁用重复切换（防竞态：后发请求覆盖先发）。
  - 空窗口 → 该区块 `Empty("○")`，其它区块不受影响。
  - 键盘：`<select>` 原生可达；按钮组可 Tab + Enter。

### I5 · 预算条 MiniBar 到 402 的提示（§3.A.1 / §3.A.3 / §3.B.4）

- **触发**：`quotaCnyUsedPct` 越过阈值，或渲染到 ≥100%。
- **反馈**：
  - `>70%` → MiniBar 变 `.y` + 旁注"预算将耗尽"。
  - `≥100%` → MiniBar 变 `.r` + chip `已用完`(.r)。
  - 升级位：客户面出现 `note.warn` "预算已用尽，调用将返回 **402**（不是限流，无需重试）→ 升级套餐"，带"升级"按钮跳 `#/plans`。
- **边界**：
  - **明确 402 ≠ 429**（README §8）：文案必须说"没钱了"而非"被限流"，避免客户端无效重试。
  - 数值缺失 → MiniBar 不渲染（`null` 分支），不显示假进度。
  - 无障碍：`role=progressbar aria-valuenow/min/max` + 百分比文本（不靠色）。

### I6 · 熔断摘除 / 恢复（§3.B.5）

- **触发**：sre 在路由策略页点"摘除上游"或"清熔断"；或系统自动熔断（`errorRateWindow` 超阈）。

- **边界**：
  - 摘除**立即生效**（不重启）；清熔断**立即**试探。

## 5. 状态与异常

### 5.1 全局状态模型

| 状态 | 触发 | 全局表现 | 令牌/组件 |
|---|---|---|---|
| **normal** | 数据就绪 | 正常渲染 | — |
| **loading** | 首载/切换窗口 | 骨架屏（首载必用，180ms 渐显） | §5.10 骨架屏 |
| **empty** | 请求成功但无数据 | `Empty` 图标 `○/▤/⚑` + 主文案 + 提示 | §5.9 |
| **partial-degraded** | 某区块数据源失败 | **仅该区块**降级为 `note.warn`，其余照常 | §5.11 分区降级 |
| **error** | 请求失败（非可恢复） | 区块内错误文案 + 重试按钮；脚本错误**不重试** | Toast `.r`（9000ms） |
| **forbidden** | 401/403 | 401 → 登录门；403 → `Empty("⛔ 无权限查看此内容")` | `--c-danger` |
| **expired** | key/会话过期 | key 行 `已过期`(.r)；会话→登录门 | `keyState()` |
| **fail-open 提示** | 治理层降级 | 静默回退，**如实**在指标显露 `precheckDegraded`（不谎报正常） | 且不阻断用户 |

**fail-open 展示原则**（阶段1 §5.2 红线3 + §6.2）：治理层异常**不阻断**用户可见流程；但**必须如实**在界面（指标页 / 可观测页）显露降级计数，**绝不用"一切正常"掩盖**。

### 5.3 空态 / 加载态 / 错误态 文案规范

- **空态**：`Empty(icon, 主文案, 提示)`；**图标区分**：`○` 无数据 / `▤` 无记录 / `⚑` 需行动 / `⛔` 无权限。
- **加载态**：骨架屏**首载必用**（避免闪屏）；加载完成 180ms 渐显；`prefers-reduced-motion` 停扫光。
- **错误态**：文案永远包含"**下一步做什么**"（受 `writeErr` 分类：400/404/409 黄、5xx/网络红）。
- **禁止**：用加载态伪装空态；用"一切正常"掩盖降级（fail-open 必须如实）。

## 7. 密钥与路由

### 7.1 密钥生命周期状态机

```text
                  ┌─────────────┐
   客户提交申请 ──▶│  申请中 pending │
                  └──────┬──────┘
             批准▼              ▼拒绝
     ┌───────────────┐   ┌────────────┐
     │ 待激活 issued │   │ 已拒绝 rejected│（终态）
     └──────┬────────┘   └────────────┘
   （一次性明文展示 / 客户端接收）
            ▼
     ┌──────────────┐  停用   ┌──────────────┐
     │  激活 active  │◀──────▶│  停用 disabled │
     └──┬────┬──────┘  启用   └──────┬───────┘
        │    │                        │删除
        │    │轮换(生成新, 旧失效)     ▼
        │    ▼                  ┌───────────┐
        │  ┌────────────┐       │ 已删除 deleted│（终态, 明文不可恢复）
        │  │ 旧 key revoked│     └───────────┘
        │  └────────────┘
        │到期
        ▼
   ┌──────────────┐
   │  已过期 expired │（不可用，可轮换换新）
   └──────────────┘
```

**状态与 chip 对照**：`申请中`(.b) / `待激活`(.b) / `激活`(.g) / `停用`(.n) / `已过期`(.r) / `已拒绝`(.n) / `已删除`(.n) / 旧 key `已轮换失效`(.r)。

**生命周期规则**：
- **申请 → 激活**：必须经审批（阶段1 §7 Q3 默认半自助，不开放免审批注册）。
- **明文 key 只显示一次**（服务端只存 sha256）——待激活/轮换后**一次性明文抽屉**。
- **轮换**：生成新 key，**旧 key 立即失效**（止血优先），面板必须显式告知（README §8）。
- **停用 vs 删除**：停用**可恢复**（临时止血）；删除**不可逆**。
- **过期**：`expiresAt` 到达 → `expired`；`≤7 天` 提前 `将过期`(.y) 预警。

### 7.2 指纹展示

- **指纹定义**：`sha256("relay-key:" + key)` 的**前 8 位十六进制**。
- **用途**：是"用户手上的 key"与"网关签发的 key"之间**唯一安全的对照物**（既不泄露明文又能一眼对齐）。
- **展示位置**：密钥表 / 一次性明文抽屉 / 401 文案 / 被拒 key 台账。
- **永不**：回显明文（有测试断言）；台账**只记指纹/提交形态/长度**。

### 7.3 一次性明文规则

| 规则 | 说明 |
|---|---|
| 只显示一次 | 关闭抽屉后不可再查看 |
| 不落库 | 服务端仅 sha256 |
| 不写日志 | whoami 的明文不写日志/不落盘/不进台账 |
| 忘记处理 | 只能**轮换**（不是"找回"） |
| 无障碍 | 抽屉 `role=dialog`，明文用 `--font-mono` + 可复制按钮 |

### 7.4 路由策略可视化

**四判据**（README §6.1）：`优先级 / 成本 / 权重 / 延迟`。原型以维度切换器 + 排序列表表达（§3.B.5）。

**档位阶梯（modelLadders）可视化**：

```text
竖向阶梯（同厂，往下推一档）        横向兜底（换供应商，同名模型）
旗舰: [ agnes-2.5-pro → agnes-3.0-flash → agnes-2.5-flash ]
平衡: [ agnes-2.5-flash → agnes-2.0-flash → agnes-3.0-flash ]
极速: [ agnes-2.0-flash → agnes-2.5-flash → agnes-3.0-flash ]
旗舰-any: [ agnes… → 落到 MiMo ]   ← 跨厂商，另起名字，不混进同串
```

- **只换模型不换厂**：同厂阶梯；跨厂商兜底**另起名字**（`*-any`），避免"往下推一档"偷偷变成"换一家供应商"。
- **能力表校验**：`tools: false` 的模型，带工具的请求**跳过**；`contextWindow` 超限**跳过**（README §3）。
- **换模型必告知**：`x-relay-model-requested` / `x-relay-model-served` / `x-relay-ladder` / `x-relay-switched` 回显（界面显示"本次由第几阶答"）。

**熔断半开可视化**（见 §3.B.5）：状态 `●健康 → ▲降级 → ◆半开（紫，区别于告警黄）→ ■熔断 → ○停用`，参数 `breakerThreshold`(默认5) / `breakerCooldownMs`。

**事故恢复三段式**：① 同请求内 failover（客户仍 200）→ ② 连续失败到阈值触发熔断 → ③ 冷却到期半开试探（成功清零切回 / 失败再熔断）。

### 7.5 本部分元信息

- **目标**：把"密钥怎么活、路由怎么选、故障怎么恢复"可视化为一屏可读的状态机与图形。
- **输入**：阶段1 §4 场景2/3、§6.2（明文只显示一次/指纹）；README §6.1（四判据）、§3（阶梯/能力表/换模型告知）、§8（指纹/轮换）、§9（三轴一闸/三段式恢复）。
- **产出物**：§7.1 密钥状态机、§7.2 指纹、§7.3 一次性明文规则、§7.4 路由/阶梯/熔断可视化。

### 10.2 新增页面规格

#### §3.B.9 租户管理 `#/tenants`（新增）

- **目标**：把 `tenantId` 从"仅创建可填"升级为**客户面强隔离**的可运营视图（REQ-07）。
- **布局**：隔离级别声明 → 租户表（tenantId/名称/隔离级别/key 数/套餐/预算占用/状态）→ 五角色 RBAC 矩阵。
- **字段表**：`tenantId / tenantName / isolationLevel（逻辑强隔离｜默认租户待迁移）/ keyCount / plan / budgetUsedPct / status`。
- **主操作**：`新建租户`（抽屉）· `详情`（抽屉）。
- **状态/边界**：越权访问返回 **403 且不泄漏他租户存在性**；`tenantId` 缺失的老数据归入"默认租户（待迁移）"。
- **权限门**：`owner/sre/finance` 可读；`auditor` 只读；`client` 不可见（在客户面仅见自身）。

#### §3.B.10 实例与分布式 `#/instances`（新增）

- **目标**：可视化 A4 短板修复——多实例下限流/配额/熔断/key 池语义一致性（REQ-01/02/09）。
- **布局**：状态外置指示（Redis 健康 + fail-open 声明）→ KPI 4 列（在线实例/Redis 健康/限流一致性/降级事件）→ 实例列表 → 一致性状态表（单实例语义 vs 多实例外置）→ 回滚方案声明。
- **字段表（实例）**：`instanceId / role(leader|worker) / version / inflight / rpmUsed/limit / startedAt / heartbeat / status`。
- **字段表（一致性）**：`capability / singleInstanceSemantics / multiInstanceExternalized / status`。
- **主操作**：`刷新实例` · `状态外置详情`（抽屉）。
- **状态/边界**：Redis 不可用 → 自动降级为实例内判定（fail-open），**不因状态层故障拒绝请求**；降级事件数应恒为 0（类似 `precheckDegraded`）。
- **权限门**：`owner/sre` 全量；`auditor` 只读。
