## 关键演示命令（可现场复现）

```bash
# 1) 底座：OpenAI 兼容转发
curl -s -X POST http://<host>:8787/v1/chat/completions \
  -H "authorization: Bearer <relay key>" -H "content-type: application/json" \
  -d '{"model":"思考-轻","messages":[{"role":"user","content":"用一句话介绍你自己"}],"max_tokens":64}'

# 2) 底座：模型清单（中文档位链名）
curl -s http://<host>:8787/v1/models

# 3) 底座：平台四件套（需管理员令牌）
curl -s -H "X-Admin-Token: <admin token>" http://<host>:8787/admin/api/tenants
curl -s -H "X-Admin-Token: <admin token>" http://<host>:8787/admin/api/plans
curl -s -H "X-Admin-Token: <admin token>" http://<host>:8787/admin/api/bills

# 4) 工作台：健康检查（仅本机）
curl -s http://127.0.0.1:8789/api/health

# 5) 验证工作台确实走底座：执行一次任务后，在 8787 请求账本中按 client key 过滤
```

## 录制方式（可复现，无头流水线）

- 环境：Ubuntu + Xvfb（1600×900×24）+ Chrome + ffmpeg x11grab
- 脚本：`/root/recorder/record.js`（puppeteer-core）+ `/root/recorder/run-record.sh`
- 分段：底座段与工作台段**分别录制再拼接**（工作台需真实执行 Agent 任务，耗时不可控，不能写死时间轴）
- 关键机制：页面就绪后再开录（`/tmp/rec-ready` → ffmpeg → `/tmp/rec-go` → 浏览 → `/tmp/rec-done`），就绪断言在错误态时拒录
- **工作台段必须断言渲染成功**：`#root` 子节点数 > 0（避免录成白屏）；CSP 修复前的白屏就栽在"只看状态码"
- 登录：底座切 admin（owner）以展示租户页；工作台用免密 token 直链，避免录制时手输口令

## 讲解话术要点（避免念稿感）

1. **问题**：Agent 落地缺两块——底座上，多上游的失败没人翻译成可执行动作；应用层，Agent 干了什么没人看得见。
2. **方案**：底座做协议统一 + 工程降损 + 平台治理；工作台做执行可见 + 审批闸 + 预算。
3. **连接**：工作台的兜底上游固定指向本机底座，模型清单从 `/v1/models` 同步——**不是并列的两个作品，是一条链路的两端**。
4. **证据**：工作台的调用能在底座请求账本里逐条找到；白屏、CRLF、端口误判三个真坑都在 PPT P14 公开。
5. **收尾**：让不稳定的上游变得可运营，让不可见的 Agent 变得可审计。
