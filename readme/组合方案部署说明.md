# 组合方案部署说明：api-relay（底座）+ CodeLens（工作台）

> 对应版本 **v1.13.0** ｜ 队伍：落幕
> 本文说明本作品**为什么是两层**、**怎么在一台机器上跑通**、以及**上线时真实踩过的坑**。
> 线上实例即按本文部署：`1.92.92.200`，1 核 / 769 MB。

---

## 1. 两层关系

| 层 | 作品 | 端口 | 回答的问题 |
|---|---|---|---|
| 基础设施层（底座） | **api-relay** | `8787` | Agent 站在什么上：模型 API 怎么聚合、失败怎么变成可执行动作、损耗怎么度量 |
| 应用层（工作台） | **CodeLens** | `8788`（对外）→ `8789`（本机） | 人怎么看见 Agent 在干什么：工具调用、参数、结果、审批闸 |

两者不是拼盘，而是**同一条链路上的上下游**：

```
浏览器 ──► nginx :8788 ──► CodeLens :8789 ──► api-relay :8787/v1 ──► 上游模型
                │                 │
                │                 └─ 模型清单从 /v1/models 定时同步（MODEL_SOURCE_URL）
                └─ Basic Auth + CSP 收敛
```

关键点：**CodeLens 不直连任何模型厂商**。它的兜底上游固定指向本机 api-relay（`TRIAL_BASE_URL=http://127.0.0.1:8787/v1`），因此底座上做的聚合、降级、归因，在工作台的每一次工具调用里都真实生效——这也是"组合"而非"两个 Demo 摆在一起"的证据。

## 2. 端口与安全边界

| 端口 | 监听 | 对外 | 用途 |
|---|---|---|---|
| `8787` | `0.0.0.0` | ✅ 安全组放行 | api-relay 网关 + 管理面板 + `/judge` 评委页 |
| `8788` | `0.0.0.0` | ✅ 安全组放行 | nginx 入口，Basic Auth + CSP 覆盖 |
| `8789` | `127.0.0.1` | ❌ **不放行** | CodeLens 本体，仅经 nginx 反代访问 |

安全组只需放行 **22 / 8787 / 8788**。`8789` 若暴露，将绕过 Basic Auth，务必保持仅本机。

## 3. 部署步骤

### 3.1 先起底座 api-relay

```bash
cd project
npm install && npm run build
node --disable-warning=ExperimentalWarning dist/cli.js serve --config relay-net.yaml
curl -s http://127.0.0.1:8787/healthz          # 期望 200
curl -s http://127.0.0.1:8787/v1/models | head # 期望返回模型清单
```

常驻：`readme/api-relay.service`（`systemctl enable --now api-relay`）。

### 3.2 在 api-relay 上开一个给 CodeLens 用的 client key

CodeLens 以普通客户端身份调用底座，密钥走服务端 `.env`，**不写入仓库**：

```bash
export RELAY_CLIENT_KEY='<在 api-relay 管理面板创建的 client key>'
```

### 3.3 打包并安装 CodeLens

```bash
# 本地构建（不要在 1C769M 的生产机上 build，会 OOM）
bash codelens/deploy/pack-local.sh          # 产出 codelens-dist.tar.gz
scp codelens-dist.tar.gz root@<host>:/tmp/

# 服务器上
bash deploy/install-server.sh /tmp/codelens-dist.tar.gz
```

`install-server.sh` 会自动：校验 Node ≥ 22.5 → 解包到 `/root/codelens` → 用 `RELAY_CLIENT_KEY` 渲染 `.env`（含 CRLF 归一化、占位符 fail-closed 校验）→ 安装 systemd unit → 重启并打健康检查。

### 3.4 配 nginx 入口

```bash
bash deploy/setup-nginx.sh
nginx -t && systemctl reload nginx
```

`deploy/nginx-codelens.conf` 已包含两处**必需**配置：

1. `auth_basic` + htpasswd（演示账号由 `setup-nginx.sh` 生成）。
2. **CSP 覆盖**（见 §5.1）：`proxy_hide_header Content-Security-Policy` + 重写 `add_header`。

## 4. 配置项要点（`/root/codelens/.env`）

完整模板见 `codelens/deploy/codelens.env.example`，重点四项：

| 变量 | 说明 |
|---|---|
| `TRIAL_BASE_URL` | 固定 `http://127.0.0.1:8787/v1`，把工作台的试用流量导给底座 |
| `TRIAL_MODEL` | **必须填 api-relay 模型清单里真实存在的模型名**。本次合并版使用 `minimaxai/minimax-m3.1-flash`（旧线上实例曾用 `glm-5.3`）；填错会在首次试用时 404 |
| `MODEL_SOURCE_URL` | `http://127.0.0.1:8787/v1/models`，每小时同步一次模型清单，保证工作台下拉框与底座一致 |
| `AGENT_MAX_CONCURRENT` | 1C769M 上必须为 `1`，否则并发任务会打满内存 |

## 5. 上线真实踩过的三个坑

### 5.1 白屏：状态码全 200，页面却是空的

**现象**：`curl` 请求 JS/CSS 全部 200，浏览器打开 `http://<host>:8788` 却是白屏。

**根因**：CodeLens 服务端（helmet）下发 `Content-Security-Policy`，其中含 `upgrade-insecure-requests`。浏览器据此把页面内的 `http://<host>:8788/assets/*` 强制升级为 `https://...`，而 8788 只监听 http，于是所有子资源 `SSL_HANDSHAKE_ERROR -107`，React 挂载点 `#root` 为空。

**修复**：在 nginx 抹掉上游 CSP 并重写一份不含该指令的：

```nginx
proxy_hide_header Content-Security-Policy;
add_header Content-Security-Policy "default-src 'self';...;script-src 'self' 'unsafe-inline';..." always;
```

一键脚本：`bash codelens/deploy/fix-csp.sh`（幂等，自动备份 `.bak.<时间戳>`，改完 `nginx -t` + reload）。

**验证方式（重要）**：不能只看状态码，要用无头浏览器渲染后看 DOM：

```bash
msedge --headless=new --disable-gpu --dump-dom "http://<host>:8788/?token=***" | wc -c
```

修复前 2,199 字节（空壳），修复后 26,416 字节（完整工作台）。

### 5.2 `KEY_MISMATCH`：Windows 的 CRLF 混进了密钥

本地编辑 `.env` 后上传，key 尾部残留 `\r`，服务端逐字节比对失败。
`install-server.sh` 已在写入前、写入后各做一次 `sed -i 's/\r$//'`，并校验"非空 + 非占位符"才允许启动（fail-closed）。

> 计量陷阱：Git Bash 下 `grep -c $'\r' file` 恒为 0，不能用它判断是否 CRLF。改用 `file file` 或 `od -c | grep '\\r'`。

### 5.3 端口探测误判：Node 说关闭，其实是开的

用 Node `net.connect` 探测 `127.0.0.1:8787` 返回 `ECONNREFUSED`，但服务实际在监听。
根因是 Node 默认走 IPv6 `::1`，而服务只监听 IPv4 `0.0.0.0`。
**结论**：端口可用性以 `Test-NetConnection`（PowerShell）或真实 `curl` 握手为准，不要用单一语言的 socket 探测当结论。

## 6. 交付前自检清单

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<host>:8787/healthz        # 200
curl -s -o /dev/null -w '%{http_code}\n' http://<host>:8787/judge          # 200
curl -s -o /dev/null -w '%{http_code}\n' http://<host>:8787/v1/models      # 200
curl -s -o /dev/null -w '%{http_code}\n' -u demo:*** http://<host>:8788/   # 200
msedge --headless=new --dump-dom 'http://<host>:8788/?token=***' | wc -c   # > 20000
ss -lntp | grep -E '8787|8788|8789'                                        # 8789 仅 127.0.0.1
```

以上 6 项在 2026-11-07 的线上实例上全部通过。

## 7. 资源约束（1 核 / 769 MB）

- **禁止**在生产机跑 `docker build` 或 `npm run build`，会 OOM；只上传构建产物。
- `AGENT_MAX_CONCURRENT=1`、`AGENT_MAX_TOOL_CALLS=30`、`AGENT_TASK_BUDGET_MS=180000`。
- 试用配额三档闸：全局 2,000,000 token/日、单 IP 300,000/日、单任务 120,000。
- api-relay 侧同样有限流与并发闸，两层都不会把机器打满。
