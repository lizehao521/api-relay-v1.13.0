## 2. 本次实际改动

1. `project/codelens/` 由 CodeLens **2.0.0 升级为 2.30.0**（旧版备份在 `.backup/codelens-2.0.0`，未进入提交包）。
2. 新增底座配置 `project/config/relay-nvidia.yaml`：
   - 两个 NVIDIA NIM provider（两把 key 权重轮换，均声明 `moonshotai/kimi-k3.1-pro`）；
   - 模型降级链 `kimi → minimax → nemotron`，TTFB 超时 5s、自动重试 0 次，kimi 无响应时快速切换；
   - 一个 `pro` 档 client key 专供 CodeLens；
   - 开启 P2 预检 / P3 归因 / P5 轨迹 / P8 度量。
3. 新增一键脚本 `project/start-combo.sh`（start / stop / status）与密钥模板 `project/combo.env.example`。
4. CodeLens 通过 `codelens/server/.env` 接入底座：
   - `TRIAL_BASE_URL=http://127.0.0.1:8787/v1`
   - `TRIAL_MODEL=moonshotai/kimi-k3.1-pro`（kimi 优先）
   - `MODEL_SOURCE_URL=http://127.0.0.1:8787/v1/models`
   - `LLM_SERVER_API_KEY=<relay client key>`
5. 工作台试用探活超时由 12s 调至 **25s**，为底座降级链预留时间（`codelens/server/src/services/agent/trial-health.service.ts`）。

## 3. 一键运行

提交包不含 `node_modules`；底座零运行时依赖，工作台首次需安装依赖（**必须用 `npm ci` 含 dev 依赖：`typescript` 是运行必需**）：

```bash
cd project
cp combo.env.example combo.env && chmod 600 combo.env   # 填入 4 个值
cd codelens/server && npm ci && cd ../..
./start-combo.sh
```

包内已带 `codelens/server/dist`、`codelens/server/dist-client` 与底座 `dist/`，无需重新构建即可启动。
如需重新构建工作台前端：`cd codelens/client && npm ci && npm run build && cp -r dist ../server/dist-client`（Linux arm64 如缺 `@rolldown/binding-linux-arm64-gnu`，补装对应版本）。

打开：

- 工作台：`http://127.0.0.1:8789`
- 底座看板：`http://127.0.0.1:8787/admin`
- 评委页：`http://127.0.0.1:8787/judge`
- 试用状态：`http://127.0.0.1:8789/api/v1/agent/trial-status`

停止：`./start-combo.sh stop`

## 5. 安全边界

- `combo.env`、`codelens/server/.env`、`data/`、`logs/` 均不进入提交包。
- 上游 key 只通过环境变量注入，不写入 YAML。
- 两个服务默认只绑 `127.0.0.1`；对外暴露需自行加 nginx + Basic Auth（见 `readme/组合方案部署说明.md`）。
- `codelens/server/.env` 由脚本首次启动生成，权限 `600`。
