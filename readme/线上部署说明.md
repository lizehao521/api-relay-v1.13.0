> 本文说明**线上实例**的接入方式、安全组约束与**就地升级 / 回滚**流程。生产部署遵循「备份 → 构建 → 校验 → 重启 → 健康检查 → 留回滚点」六步。

## 2. 网络（安全组）

云安全组放行 **22 / 8787 / 8788**（入方向 `0.0.0.0/0`，策略允许）。

| 端口 | 监听地址 | 对外 | 说明 |
|---|---|---|---|
| `8787` | `0.0.0.0` | ✅ | api-relay 网关 / 管理面板 / `/judge` |
| `8788` | `0.0.0.0` | ✅ | nginx 入口：Basic Auth + CSP 覆盖 → 反代 8789 |
| `8789` | `127.0.0.1` | ❌ **禁止放行** | CodeLens 本体，暴露即绕过鉴权 |

> 8788 的 CSP 必须由 nginx 覆盖上游响应（去掉 `upgrade-insecure-requests`），否则浏览器会把子资源强制升级为 https 导致**白屏**。根因、修复与验证方式见 `readme/组合方案部署说明.md` §5.1。

## 3. 就地升级流程（v1.11.0 实操记录，2026-10-28）

```bash
# ① 备份（配置 + 数据 + 环境变量 + 旧源码/产物 + systemd 单元）
TS=$(date +%Y%m%d-%H%M%S); B=/root/backup-$TS; mkdir -p $B
cd /root/api-relay
tar -czf $B/code-config.tar.gz config data .relay.env relay-net.yaml \
    package.json package-lock.json tsconfig.json src dist dist-admin frontend/src scripts
cp /etc/systemd/system/api-relay.service $B/; ln -sfn $B /root/backup-latest

# ② 上传源码更新包（本地打包后 scp；此处以 tar 为例）
scp -i <key> relay-src-update.tar.gz root@1.92.92.200:/tmp/
ssh -i <key> root@1.92.92.200 'cd /root/api-relay && tar -xzf /tmp/relay-src-update.tar.gz'

# ③ 构建（后端 tsc + 前端 vite）
npm run build

# ④ 部署前校验（配置 / 环境变量 / 分层策略）
set -a && . ./.relay.env && set +a
node --disable-warning=ExperimentalWarning dist/cli.js check --config config/relay.yaml

# ⑤ 重启（重启前确认 healthz 的 inflight=0，避免打断在途请求）
systemctl restart api-relay && sleep 5 && systemctl is-active api-relay

# ⑥ 健康检查
curl -s http://127.0.0.1:8787/healthz
curl -s -H "X-Admin-Token: $RELAY_ADMIN_TOKEN" http://127.0.0.1:8787/admin/api/health
```

**v1.11.0 升级验证结果**：`/healthz` 200（version 1.11.0）· `/admin` 200（引用新 `index-DYsP0nSt.js`）· `/judge` 200 · `/v1/models` 200 · `/admin/api/{tenants,roles,plans,bills,recon}` 全部 200 · `NRestarts=0`。

## 5. 安全与运维要点

- **密钥一律走环境变量 / 受保护文件**，配置文件用 `{ENV:NAME}` 插值，终端与对话中不明文粘贴。
- 不要设 `NODE_TLS_REJECT_UNAUTHORIZED=0`（会全局关闭 TLS 校验）。
- 单实例限流/额度为单实例口径（多实例部署需注入共享 state）；详见 `healthz.limits` 提示与 `project/docs/DEPLOYMENT.md`。
- 改配置需重启（`relay-net.yaml`/`relay.yaml` 仅在进程启动时读入）。
