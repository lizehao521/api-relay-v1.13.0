## 1. 商户 token 券闭环（M0，核心）

把「线下到店消费」折算为「线上 AI 权益」的核销闭环。M0 为概念验证版本：静态券 + 管理接口驱动，**不改前端**。

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 额度池 | `project/src/merchant/quota.ts` | 购买 / 发行 / 剩余额度；`status='active'` 才可领券 |
| 发券 | `project/src/merchant/voucher.ts` | 面额券；防超发：`剩余 = 购买 − 已发 − Σ(未用/已领券面额)` |
| 领券发 Key | `project/src/merchant/voucher.ts` | 复用 `KeyManager.create()`，`origin='voucher'` |
| 核销计费 | `project/src/merchant/voucher.ts` | 写 `store_redemption`（含 `status`），与 `meter` 联动 |
| 管理接口 | `project/src/admin/handlers/merchant.ts` + `src/admin/api.ts` | 6 条 `/admin/api/merchant/*` 路由（quota / vouchers / claim / redemptions） |
| 权限 | `project/src/admin/rbac.ts` | 新增 `merchant.read` / `merchant.write`（operator 两者、viewer 只读） |

治理约束（均由测试锁定）：

- 券 Key **不可 `rotate()`、不可硬删**（`origin='voucher'` 双重拦截）——避免一券换多 Key 重复兑现面额。
- 重启恢复**保留 `origin`**，券 Key 重启后仍可鉴权且不被误判为面板 Key。
- 营销链路 **fail-open**：券服务故障不影响已签发 Key 调用。
- 状态机：券只能被领取一次（`UPDATE ... WHERE status='unused'` 原子占位）；20 并发同券只成功 1 次。
- `SqliteStore.query()` 只读、写必须走 `execute()`；券/额度池测试使用真实 `SqliteStore` 临时库。

> 说明：存储层沿用 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE` 吞异常，**没有版本化迁移框架**。
