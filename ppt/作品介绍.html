方案设计 ① 降损三件套，建在核心链路

P2 · 调用前
预检

上游之前拦下「必然被拒」的请求：畸形 tool_calls、超长输入……省一次往返与计费。

P3 · 失败时
归因

raw error → {failure_reason, suggested_next.action, recoverable, retryAfterMs}

15 类归因 × 11 个可执行动作。

P8 · 持续
量化

归因投递率 / 自动恢复 / 无效重试 / 治理层自身开销。没有度量就没有优化。

关键区分：429 + 余额不足 → quota_exhausted + top_up_balance（不可重试）；余额不足回 402 而非 429——不让 Agent 浪费一次重试。

创新亮点

01 错误可执行化

行业首个把「失败对 Agent 可执行」作为第一设计原则的中转站——竞品逐行比对佐证（file:line 级证据存档）。

02 同价承诺

free 层错误体与上游字节一致——降损能力不成为加价理由。

03 防彩虹表指纹

sha256("relay-key:"+key) 域前缀设计——裸哈希可被字典反推，域前缀让彩虹表失效。

04 零运行时依赖

供应链攻击面为零；部署只需一个 Node 二进制。

05 损耗可度量（P8）

连「治理层自身开销」也纳入量化——自我约束，降损层自己也要被降损衡量。

组合方案 ② 上线路上踩过的三个真坑

坑 1 · 状态码会骗人
白屏，但资源全 200

CSP 里的 upgrade-insecure-requests 把 JS 强制升级到 https，而 8788 只有 http；headless + netlog 抓到 SSL_HANDSHAKE_ERROR -107。

修复后 DOM 2,199 → 26,416 字节

坑 2 · 工具也会骗人
CRLF 导致 KEY_MISMATCH

Windows 工作副本让 .env 尾部残留 \r；Git Bash 的 grep 把 CR 当行结束，grep -c $'\r' 恒为 0。

改用字节级双方法复核

坑 3 · 结论要能自我推翻
SSH 端口误判

Node net.connect 报 ECONNREFUSED，一度判定「sshd 未运行」；换 .NET TcpClient / curl 实测为 OPEN。

多方法交叉验证后纠正

三个坑的共同点：表层指标都正常。200 不代表能渲染，grep 为 0 不代表没有 CR，连接被拒不代表服务没起。全过程证据留档于 codearts_proof/04，错误结论原样保留。
